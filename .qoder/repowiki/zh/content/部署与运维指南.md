## 部署路径

- **在线**：`cd deploy && cp .env.example .env`（改密钥）→ `docker compose up -d --build`
- **纯内网离线**：构建机 `bash scripts/export_images.sh export` → 拷贝 tar 包 + deploy/ 目录 →
  部署机 `export_images.sh import` → `docker compose up -d`（不带 --build）
- 访问 `http://<IP>:8080`；初始 admin 密码：`.env` 的 `ADMIN_INITIAL_PASSWORD`，留空则随机生成打印在 api 日志（`docker logs opspilot-api | grep 初始`）。

## 配置要点（.env）

- **必改**：`MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` / `JWT_SECRET_KEY`（`openssl rand -hex 32`）。
- **强烈建议**：`SECRET_ENCRYPT_KEY`（`openssl rand -base64 32`，AES-256-GCM 字段加密主密钥）——
  **丢失即无法解密已存 MFA secret 与 SSH 凭据**，必须离线留存。
- `.env` 解析：docker compose v2 与 pydantic-settings 均支持单/双引号包裹并自动剥离；
  含 `#`/`$`/空格的密码**用单引号**最安全（双引号内 `$` 会被 compose 插值展开）。
  例外：`docker run --env-file` 不剥引号，勿混用。
- 修改 `.env` 后需 `docker compose up -d api worker` 重建生效。

## 备份与恢复

- `bash deploy/scripts/backup.sh` → `deploy/backup/<时间戳>/{mysql_opspilot.sql, exec_logs.tar.gz}`；
  建议 crontab 每日 02:00。Redis 仅队列/缓存无需备份。
- 恢复命令见 [DEPLOYMENT.md §9.2](file://deploy/DEPLOYMENT.md)；恢复后 `docker compose restart api worker`。
- 升级前必做：备份 + 业务镜像打 `rollback` 标签；回滚时若新版本已执行迁移需同时恢复数据库。

## 验证与测试

```bash
curl -s http://localhost:8080/healthz                # 整链路探活
curl -s http://localhost:8080/api/v1/ping            # 公开探活接口（code=0）
docker cp deploy/smoke_v2.py opspilot-api:/tmp/      # 冒烟：模板→工单→审批全链路
docker exec -e PYTHONPATH=/app -w /app opspilot-api python /tmp/smoke_v2.py
docker exec opspilot-api python -m pytest tests/ -q  # 后端测试套件（16 个测试文件）
```

## 高频运维陷阱

| 陷阱 | 说明 |
| --- | --- |
| 改 `.env` MySQL 密码不生效 | 环境变量密码**仅数据卷首次初始化时生效**；已建卷后改密需进容器 `ALTER USER` |
| worker 重启后任务状态 | queued 自动重认领重跑；running/paused 标 `interrupted` 落原因，需人工重新发起 |
| Excel 导入 413 | nginx `client_max_body_size 50m` 限制 |
| WebSocket 频繁断连 | 本机 nginx 已配 3600s；若前置还有 LB 需在其上放开 Upgrade 与空闲超时 |
| 本机开发环境 | 宿主机无 Python/Node，构建与测试一律走 Docker 容器内执行 |
