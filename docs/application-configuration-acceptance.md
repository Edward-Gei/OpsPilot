# 应用配置本地验收

当前迁移至 `0023`。提交草稿后在“待办审批”通过会自动创建远端发布任务；审批通过不等于远端发布成功，Worker 写入且回读一致后才成为正式版本。暂时性平台故障最多自动重试 3 次（间隔 2、4、8 秒），不确定写入只重试回读，普通人工重试也不会重复写入；漂移及确定性拒绝不重试。版本列表不再提供常规“发布”，仅最终失败且无漂移的已批准版本可人工“重试发布”；漂移仍在对比弹窗处理。对比弹窗确认重新发布时携带最近同步快照 ID，Worker 仅在远端仍与该快照一致时覆盖；快照过期需重新同步确认，普通审批发布仍使用候选版本原有基线。明确确认漂移覆盖属于新的人工操作，不继承旧任务的不确定写入标记。

在 `deploy/` 中使用 `docker compose --env-file .env -f docker-compose.yml -f docker-compose.acceptance.yml up -d --build` 启动。覆盖文件将项目、容器和持久化卷与现有 OpsPilot 部署隔离，并将工作树后端源码只读挂载到 API/Worker；本地 `.env` 将 `NGINX_HTTP_PORT` 设为 `127.0.0.1:53022`。访问地址为 `http://127.0.0.1:53022/`。

验收覆盖将 API 和 Worker 容器内的 `stage-admin.mitrade.com` 固定解析为 `119.28.109.141`，不修改宿主机 DNS、常规部署或其它服务容器。若该地址变更，需同步更新覆盖文件并重建这两个容器。

本次本地验收已事先在 `opspilot-config-test:local` 容器镜像中安装依赖并执行全量测试。若网络下载较慢，可使用 `docker compose --env-file .env -f docker-compose.yml -f docker-compose.acceptance.yml up -d --no-build` 复用该本地镜像；新机器没有此镜像时仍需执行上面的 `--build`。此覆盖仅用于本地验收，不代替常规生产镜像构建。

启动前在隔离工作树的、被 Git 忽略的 `deploy/.env` 中生成随机且稳定保存的 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`JWT_SECRET_KEY`、`SECRET_ENCRYPT_KEY` 和 `ADMIN_INITIAL_PASSWORD`，不要使用 `.env.example` 中的占位值，不要提交该文件。首次启动会自动迁移并初始化管理员；使用 `.env` 中的初始密码登录 `admin` 后须先完成强制改密，才能访问受保护的应用配置页面。现有种子流程也会在 API 启动日志中打印初始密码，勿转发该日志，首次登录后立即改密。若保留数据卷以供再次启动，必须复用相同的数据库密码与加密主密钥，否则旧数据无法解密。

本地验收应检查健康检查、迁移版本、应用配置菜单、实例与凭据选项、新建/发现、审批、手动同步和漂移视图。无真实 Apollo/Nacos/Consul 服务的环境只能验证本地 UI、权限、数据库及离线适配器契约；真实平台兼容性状态以[兼容性记录](./application-configuration-provider-compatibility.md)为准。停止验收服务不要加 `-v`，以免误删独立卷。

配置文件列表的“查看”进入只读详情，“编辑”进入可操作详情，编辑按钮沿用应用管理列表的蓝色样式；已归档行对具备 `config:delete` 的用户显示“删除”，确认后仅删除 OpsPilot 本地管理记录并刷新列表，不影响远端。列表通过搜索框回车查询，平台实例按钮沿用与页面主色协调的青色操作样式。详情信息格采用均衡的固定列宽，长远端定位可换行；详情不再提供审批按钮或任务页签。工单与配置审批统一在“待办审批”的两个页签中处理，配置审批可脱敏预览候选内容；仅配置审批角色成员即使没有 `ticket:approve` 或 `config:read`，也能访问待办页。点击同步不展示后台任务提示框，详情页同步按钮在任务完成前显示加载动画，完成后在当前页提示成功或错误；列表不展示最近接入任务历史。漂移处理和版本记录中的内容查看均使用居中弹窗，版本查看不切换页签。关联应用名称直接显示在详情信息格中，不再单独设置页签，仍通过“编辑信息”维护。草稿操作按钮按保存、提交和丢弃区分颜色并配图标。

列表每个配置文件的“同步”从请求开始到任务结束独立显示加载状态，任务结束后刷新列表并提示结果；检测到漂移仍打开对比弹窗。漂移确认导入或重新发布成功后弹窗自动关闭，失败时保留弹窗及错误提示。YAML、JSON 和 Consul KV 正文沿用 CodeMirror 编辑器显示缩进引导线；properties 与 TEXT 仍使用普通文本输入框。

新建配置文件使用居中弹窗，须先选平台实例；手工模式随后展示对应平台的远端定位字段，并须显式选择审批角色；取消并再次打开会清空未提交的输入。发现模式可多选远端资源并分别填写接入信息。点击“接入选中配置”创建任务成功后，同一弹窗切换为配置接入进度，展示已处理数量、成功/跳过/失败计数与逐项结果；接入仅读取远端并写入 OpsPilot，不向远端发布。关闭进度窗不取消后台任务，再次打开时若任务仍在运行可查看进度；任务完成后刷新配置文件列表并提示结果，列表顶部不重复展示任务提示。Nacos 发现模式选定实例后自动读取命名空间选项，以名称和 ID 展示，支持默认 `public`、加载失败重试与切换实例后清空旧选择；手工模式仍可直接输入定位字段。浏览器验收已覆盖列表筛选、只读与编辑入口、平台连接测试、发现多选、本地新建与关联、草稿提交、待办审批、手动同步及归档；远端发布、实际漂移处理和真实远端资源接入未在生产 Nacos 实例上执行，以免改动外部配置。

Nacos 手工新建时，Namespace 自动读取远端目录，Group 在聚焦时从当前命名空间的配置发现结果提取候选；两者均可选择或自行输入，并可按显示名称或 ID 筛选。默认 `public` 在表单中显示名称，提交定位器时使用空 Namespace ID。候选获取失败时显示重试入口，不阻断手工填写；切换实例或 Namespace 会清空不再适用的候选。Apollo 与 Consul 手工定位保持原输入方式。
