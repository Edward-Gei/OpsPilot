# 应用配置平台兼容性记录

本文区分离线适配器测试与真实平台联调，记录已知厂商限制。下表来自既有联调记录，本次文档整理未重新测试真实平台，也未重新查询最新发行版。使用步骤见[应用配置使用与验收](./应用配置使用与验收.md)。

## 2. 平台契约

### Apollo

- 只管理生产环境 `PRO`。发现使用 `GET /openapi/v1/envs/PRO/apps/{appId}/clusters/{cluster}/namespaces`，读取最新版本使用 `GET .../namespaces/{namespace}/releases/latest`。
- 首次创建私有 Namespace 使用 `POST /openapi/v1/apps/{appId}/appnamespaces`；须先确认 PRO 集群存在，再创建 Item 并发布 Release。已有 Namespace 但无 Release 时可直接创建 Item 后发布。
- 私有 YAML、JSON Namespace 名称带对应文件后缀；不提供 TEXT Namespace，OpsPilot 只开放 properties、YAML、JSON。
- 操作账号须在 Apollo 存在，并取得修改、发布及新建 Namespace 所需权限。若启用“编辑者不得自行发布”的 Namespace 锁，当前单一操作账号可能被拒绝，需要在真实平台验证。

### Nacos

- 先通过 `/nacos/v1/console/namespaces` 获取命名空间名称与 ID，再分页读取 `/nacos/v1/cs/configs` 的 `pageItems` 和 `totalCount`。
- 默认 `public` 的 Namespace ID 与配置 API 的 `tenant` 均使用空字符串；命名空间目录无权限时可手工填写定位。
- 2.2.3 的历史现场请求需要显式携带空 `dataId` 和 `group`，有筛选值时再覆盖；其他版本需分别确认。
- 写入前按精确 `tenant/group/dataId` 复读。已记录的另一实例只完成命名空间列表与选定命名空间发现，未核对版本；其默认命名空间无配置，不能据此确认该路径的完整读取行为。

### Consul

- 前缀发布通过 `/v1/txn` 完成，最多 64 个 KV 操作。
- 对已读取键执行 CAS/索引校验；读取后的新键插入不受该事务锁定。
- 需要分别验证 ACL 权限、前缀边界、多键写入及事务失败行为。

## 3. 并发与写入限制

Apollo、Nacos 没有已验证的厂商原子 CAS 发布保障。OpsPilot 在写前再读、写后回读，但最后一次读取后仍可能发生外部并发修改。Consul 的已读键 CAS 也不能消除前缀中新插入键的并发窗口。

写入结果未知时只重试回读，普通人工重试继承这一限制；明确确认漂移覆盖会创建新的人工发布操作。应结合平台权限与外部变更管理使用，不能将上述机制表述为所有平台均支持原子条件发布。

## 4. 后续真实联调

在明确授权的隔离资源上，逐版本记录以下结果：

1. 认证、权限拒绝、发现分页、精确定位和已发布配置读取。
2. 首次创建、已有资源更新、正文格式与注释保留。
3. 发布后回读、超时未知结果、自动退避与人工重试。
4. 远端并发改动、漂移导入、确认重新发布及快照过期。
5. Apollo 单账号发布限制、Consul 多键事务和各平台版本差异。

记录平台版本、日期、操作及通过/失败结果、脱敏后的响应类型和未覆盖项。不得保存 Token、密码、配置正文或 URL 中的敏感参数。
