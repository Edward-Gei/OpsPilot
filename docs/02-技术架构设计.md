<!-- v2.2 变更: 前端行说明去掉"/WS" -->

**关键取舍说明**

1. **不用 Celery/RQ**：作业是长时运行、需要中途"停止/继续"、实时回传日志的交互式任务，Celery 的任务模型（短任务、结果回调）不匹配；自研 asyncio Worker 用 `asyncssh` 连接作业主机执行步骤，控制信号走 Redis，模型更简单直接。
2. **日志存文件、元数据存 MySQL**：多步骤 × 大量输出的日志若全进 MySQL 会造成大表；日志按 `执行ID/步骤ID` 落盘（共享卷），MySQL 只存状态与摘要；前端实时展示直接长轮询 REST 读文件增量（WebSocket 已弃用，见 §4.3），状态事件回放走 Redis。
3. **API 与 Worker 分进程**：执行高峰不影响 Web 请求；单机 Compose 内以两个容器部署，共享代码库。

## 3. 认证与权限架构

### 3.1 认证流水线

```
登录请求 → AuthProvider 链（local → ldap → oidc 回调）→ 认证成功
        → MFA 策略检查（off/optional/required）
            ├─ 需要 TOTP：签发 mfa_token(短时、仅限 /auth/mfa/*) → 校验 TOTP → 签发正式令牌
            └─ 不需要：直接签发 Access(15min) + Refresh(可配置，默认7d)
```

- **AuthProvider 抽象**：`authenticate(username, password) -> UserIdentity | None`；LDAP/OIDC 首次登录自动建用户（来源标记 + 默认角色，配置项）。
- **OIDC**：授权码模式，`/auth/sso/oidc/login` 重定向至 IdP、`/auth/sso/oidc/callback` 回调后重定向前端 `/login?ticket=xxx`、`/auth/sso/exchange` 用一次性 ticket 换正式令牌（复用三态登录出口，受 MFA 策略约束）、`/auth/sso/options` 供登录页判断是否展示 SSO 入口；按 `sub/email` 映射本地用户，首登自动建用户。
- **令牌管理**：JWT 无状态校验；登出/重置密码时将 Refresh 的 `jti` 写入 Redis 吊销集合（TTL=剩余有效期）；Access 短时效自然过期。
- **个人访问密钥通道**：`get_current_user` 识别 Bearer 凭证的 `opsp_` 前缀——命中则走 `api_token` 表 SHA-256 哈希查表鉴权（过期/账号状态校验，`last_used_at` 60 秒节流更新），否则走 JWT 解码；密钥通道请求打 `api_token_auth` 标记，密钥管理接口（`/user/tokens`）据此拒绝密钥自身调用（防自我繁殖）。
- **登录保护**：失败计数存 Redis `login:fail:{username}`，超限锁定（写 DB 锁定字段 + 审计）。

### 3.2 RBAC 鉴权

- 权限点常量表（代码内枚举 + 初始化写库），角色-权限、用户-角色多对多。
- FastAPI 依赖注入实现：`require_perm("ticket:approve")`；用户权限集合登录时计算并缓存在 Redis（角色变更时失效）。
- 前端按权限点控制菜单/按钮显隐；后端为最终裁决。
- 聚合类接口（工作台概览 `/dashboard/summary`、全局搜索 `/search`）不挂独立权限点：登录即可调用，接口内部按调用者权限集合动态裁剪返回段（无权段为 null），避免为跨模块只读聚合新增权限点。

### 3.3 敏感数据加密

| 数据 | 方案 |
| --- | --- |
| 用户密码 | bcrypt（cost 12） |
| SSH 凭据（密码/私钥）、MFA secret | AES-256-GCM，主密钥 `SECRET_ENCRYPT_KEY` 来自 .env（32 字节 base64）；密文格式 `nonce + ciphertext + tag`，字段级加密 |
| JWT 签名 | HS256，`JWT_SECRET_KEY` 支持配置双密钥轮换（新签旧验） |

### 4.1 数据流与生命周期

<!-- v2.2 变更: 整段重写。删除 Shell/Ansible 双执行器分支，统一为步骤执行器 SSH→作业主机 -->

```
工单审批通过（或免审提交）
  │ API: 工单→queued（排队中），创建 execution + steps 记录（全部 pending）
  │      XADD ops:exec:queue {execution_id}
  ▼
Worker 调度器（Redis Stream 消费组，单机可多协程消费；认领即 XACK，工单/execution→running）
  │ 逐步骤串行调度：step[i] 开始 → 渲染模板参数 → SSH 连接作业主机
  ▼
┌─ 步骤执行器（统一） ─────────────────────────────────────────────┐
│ SSH 连接模板配置的作业主机 → 在 workspace 创建本次执行的工作目录      │
│ → 上传渲染后脚本（Shell 脚本 / Ansible playbook+inventory）        │
│ → 执行脚本 → 流式读 stdout/stderr 推日志                           │
│ → 脚本执行完毕，取进程退出码判定步骤成败                             │
│ → 清理本次工作目录（保留日志文件）                                  │
│ 全局并发上限为配置项（exec.global_concurrency，默认50），V1 未强制实施信号量          │
└──────────────────────────────────────────────────────────────────┘
  │ 每行输出：写本地日志文件 + PUBLISH ops:log:{execution_id}
  │ 步骤状态变更：写 MySQL + PUBLISH ops:event:{execution_id}
  ▼
步骤全部完成 → 按失败策略决定进入下一步骤 / 中断
全部步骤完成 → execution 汇总 → 按终态映射表更新工单 → 投递通知事件 → 审计
```

> **概念澄清**：「作业主机」（job_host）= Jenkins agent = 通用执行节点：替平台执行 Pipeline 步骤的机器。平台只 SSH 连接作业主机；作业主机是否再去连接其他目标机器（如 Ansible 管控的受控节点），是步骤脚本自己的事，平台不感知、不管理目标机器。作业主机 ≠ CMDB 主机，两者不得混用同一配置/数据入口。CMDB（主机/应用）退化为资产台账，与工单执行完全解耦。管理员在系统设置维护作业主机列表（CRUD + 连通性测试 + 启用/禁用），每台绑定一条 SSH 凭据；模板配置时单选其一，工单提交时固化作业主机快照。

### 4.2 执行控制实现

<!-- v2.2 变更: 控制表重写——删除并发数/分批/批间确认行；暂停/恢复/中止/强杀的作用对象从"主机/目标"平移到"步骤/当前步骤进程"；
     检查点从4个简化为3个 -->

| 操作 | 触发方 | 实现机制 |
| --- | --- | --- |
| 超时 | 执行策略/模板 | `asyncio.wait_for` 步骤级；超时置 `timeout` 并按失败策略处理 |
| 失败中断 | 执行策略 | 步骤结束检查：`fail_fast=true` 时中断后续步骤（后续步骤置 `skipped`） |
| 暂停 pause | 用户（API） | 仅 running：写 `ops:ctrl:{eid}=pause` 并 PUBLISH；调度器检查点在当前步骤跑完后停住、不进入下一步骤，execution/工单置 `paused` |
| 恢复 resume | 用户（API） | 仅 paused：写 `ops:ctrl:{eid}=resume`，调度器从下一步骤继续 |
| 中止 abort | 用户（API） | queued/running/paused：写 `ops:ctrl:{eid}=abort`；不再执行后续步骤，当前在跑步骤默认不打断、跑完后 execution 置 `terminated`，工单置 `interrupted(user_abort)`，后续步骤置 `skipped` |
| 强制中止 force-abort | 用户（API） | running/paused：在中止基础上 kill 作业主机上当前在跑步骤进程 `conn.abort()` 强杀（best-effort），当前步骤置 `terminated`；高风险操作，独立审计 |
| 撤销 cancel | 用户（API） | 仅「审批中」且模板允许撤回，纯状态机流转，不进队列，工单置 `cancelled` |

- **调度器检查点**（信号响应位置）：① 认领消息开跑前（覆盖 queued 期间下发的信号）；② 每步骤开始前；③ 每步骤结束后。不依赖 queued 瞬间窗口。
- **终态映射**（execution → 工单）：`success→success`；`failed→failed`（含步骤级 timeout 聚合，详情按步骤标注）；`terminated→interrupted(user_abort)`；`interrupted→interrupted(system_crash/worker_lost)`；步骤级 `skipped` 为步骤级标记不影响工单终态。
- **ACK 时机**：Worker 认领消息、execution queued→running 的同一时刻立即 XACK，使 queued/running 两阶段崩溃可区分。
- **崩溃恢复（三分支）**：Worker 启动时——① Stream pending 未 ACK 消息（queued 阶段崩溃）用 `XPENDING + XCLAIM` 重新认领正常重试（功能等价 XAUTOCLAIM 的两步实现）（尚未执行过命令，重跑安全），仅 `delivery_count` 超阈值（默认 3）才 ACK 丢弃并置 `interrupted(worker_lost)`；② DB 中 `running` 的 execution（已 ACK 后崩溃）置 `interrupted(system_crash)`，步骤状态保留现场；③ `paused` 的 execution 调度上下文已丢失（V1 不承诺断点续跑）同样置 `interrupted(system_crash)`。工单同步置 `interrupted` 并落 `interrupt_reason`；崩溃恢复写系统事件审计（`worker_crash_recovered`，含 worker_id/execution_id/ticket_id/reason）并通知提交人与 admin（走通知集成 + 系统事件日志，V1 不引入告警中心）。

### 4.3 实时日志通道（长轮询；WebSocket 已弃用）

<!-- v2.2 变更: 日志路径从三级(执行ID/步骤ID/主机ID)改为二级(执行ID/步骤ID)；
     "切换主机" → "切换步骤"；日志维度从"按主机"改为"按步骤" -->

```
Worker ──XADD──► Redis(ops:event:{eid} 事件列表) ◄──读取── API /events 长轮询 ──► 浏览器
   └──append──► 日志文件 /data/logs/{eid}/{step}.log ◄──读取── API /logs 增量 ──► 浏览器
```

- **状态事件**：前端 `GET /executions/{eid}/events?since_seq=` 长轮询循环（服务端有新事件立即返回，否则挂起至 30s；挂起前归还 DB 连接避免连接池耗尽），`finished=true` 结束轮询。
- **实时日志**：前端每 2s 对"已开跑且未完成"的步骤按 `GET /executions/{eid}/logs?step_order&offset=` 行偏移增量拉取（Jenkins 式尾随）；单日志框按步骤顺序合并展示全部步骤日志（分隔行区分步骤），点击步骤节点在日志框内定位到该步骤起始，无订阅状态。
- **日志路径格式**：`/data/logs/{execution_id}/step_{step_order}.log`
- **日志维度**：按 **执行ID / 步骤序号** 落盘（每步骤一个日志文件）
- **WS 弃用说明（2026-07）**：原 `/ws/executions/{eid}?token=` 网关因执行范式改造后订阅失效导致日志无法实时更新，且断线重连/令牌过期链路复杂，已摘除注册；代码保留在 `app/api/ws_deprecated.py`，回切需恢复 `main.py` 注册与 nginx `/ws/` 代理。Worker 侧 `ops:log:{eid}` Pub/Sub 推送保留（与落盘同在 100ms 聚合链路，开销可忽略，当前无消费方，回切 WS 时直接复用）。
- 日志文件随审计保留策略同周期清理。

### 4.4 模板渲染与安全

<!-- v2.2 变更: 内置变量去 host_ip 等目标主机变量；五重快照"主机清单"→"作业主机快照" -->

- 参数渲染用 Jinja2 **沙箱环境**（SandboxedEnvironment），仅允许工单参数与内置变量（`ticket_id`、`job_host_ip`、`step_name` 等）。
- 工单提交时固化六重快照：作业主机、步骤脚本内容、审批节点、执行策略、模板版本、引用凭据 → 存入工单，审批人看到的即最终执行的。其中引用凭据（credential_refs）冻结为 `[{alias, credential_id, credential_name}]` 快照，不落任何密文。
- 凭据仅在 Worker 进程内存中解密使用（作业主机连接凭据与脚本引用凭据），不落日志、不进 API 响应。

### 4.5 凭据环境变量注入（脚本调用凭据）

模板可声明引用凭据（credential_refs，`[{alias, credential_id}]`），shell 步骤执行时按别名注入环境变量供脚本读取：

- **命名**：`CRED_<ALIAS大写>_USER` / `CRED_<ALIAS大写>_SECRET` / `CRED_<ALIAS大写>_PASSPHRASE`（无口令时不注入第三项）。
- **注入方式**：Worker 执行步骤时按工单快照中的 credential_id 实时取密文解密，以 **stdin 前置 export 行** 注入 shell 会话（单引号安全转义），不写入落盘脚本文件、不出现在命令行/进程列表。
- **安全边界**：明文仅存在于作业主机上该步骤进程的环境变量中；执行日志、工单快照、API 响应均不含密文（脚本自身 `echo` 密文除外，由模板编写规范约束）。
- **生命周期**：提单时冻结 alias+credential_id+credential_name；凭据密文后续轮换不影响引用关系，执行时永远取最新密文；被引用的凭据受删除保护（42201）。

## 5. 通知与审计架构

### 5.1 通知（异步、可插拔）

```
业务事件(审批提醒/通过/驳回/执行成功/失败)
  → notify_service.emit(event, payload)  # 写 notification_record(pending) + XADD ops:notify:queue
  ├─ 站内信（NOTIFY-06）：同事务解析收件人用户名 → 每人写一行 user_notification
      （不受渠道启用/事件映射影响；顶栏铃铛 30s 轮询未读数消费）
  → Worker 通知分发器：按事件-渠道映射取启用渠道 → 并发发送
      ├─ EmailChannel(SMTP)  ├─ WebhookChannel(HMAC-SHA256 签名头)  ├─ TeamsChannel(Incoming Webhook Card)
      └─ 预留：DingTalk/Feishu/WeCom（实现 NotifyChannel 抽象即接入）
  → 失败重试：指数退避(1m/5m/15m，默认3次)，notify_dispatcher 内置 30s 周期扫描循环（asyncio 后台任务）扫 pending/failed
  → 结果回写 notification_record
```

`NotifyChannel` 抽象：`send(event, rendered_content, config) -> Result`；渠道配置存 DB（管理员全局一份），敏感项（SMTP 密码）字段级加密。

### 5.2 审计

- **写入路径**：service 层显式调用 `audit.log(actor, module, action, target, result, detail)`；登录/登出等在认证流程内嵌。异步落库（后台任务队列，避免阻塞请求），进程退出前 flush。
- **不可篡改**：应用层无 UPDATE/DELETE 接口；MySQL 账号对 `audit_log` 表可只授予 INSERT/SELECT（部署脚本可选强化）。
- **保留与清理**：Worker 内 APScheduler 每日按 `AUDIT_RETENTION_DAYS` 删除过期分区数据；`audit_log` 按月 RANGE 分区，清理即 DROP PARTITION，避免大表 DELETE。
- **导出**：查询条件透传，服务端流式生成 CSV/Excel（限制单次导出上限，如 10 万行）。

## 7. 部署架构（Docker Compose）

```yaml
# deploy/docker-compose.yml 拓扑（示意）
services:
  nginx:    # 对外唯一入口 NGINX_HTTP_PORT(默认8080)→80；静态资源 + /api /healthz 反代
  api:      # backend 镜像，ENTRYPOINT 脚本(RUN_MIGRATIONS=1 执行 alembic upgrade head) + CMD=uvicorn app.main:app
  worker:   # 同一 backend 镜像，CMD=python -m app.worker_main（RUN_MIGRATIONS=0）
  mysql:    # 8.0，卷 mysql-data；init SQL 建库
  redis:    # 7，开启 AOF，卷 redis-data
volumes: mysql-data, redis-data, exec-logs(api 与 worker 共享)
networks: 内部 bridge，仅 nginx 暴露端口
```

- **配置**：全部经 `.env` 注入（数据库、Redis、JWT/加密密钥、审计保留天数、步骤并发上限等）；`.env.example` 为唯一配置清单来源。
- **初始化**：api 容器启动时（RUN_MIGRATIONS=1）先执行 `alembic upgrade head`，再在应用 lifespan 内幂等执行种子数据（权限点/内置角色/admin 初始账号，首登强制改密）；worker 依赖 api 健康后启动，天然避免并发迁移。
- **内网离线**：镜像在有网环境构建后 `docker save/load` 或推送内网私有仓库；前端构建产物打入 nginx 镜像。
- **健康检查**：各服务 healthcheck；api `/healthz`（含 DB/Redis 探活）。

## 8. 安全设计清单

| 项 | 措施 |
| --- | --- |
| 传输 | 内网可 HTTP；nginx 预留 TLS 配置块（自签/企业 CA） |
| 注入 | ORM 参数化；Pydantic 严格校验；模板渲染 Jinja2 沙箱 |
| XSS/CSRF | 前端默认转义；JWT 走 Authorization 头（非 Cookie），CSRF 面收敛 |
| 越权 | 全接口 `require_perm`；对象级校验（如仅创建人可撤销工单） |
| 凭据 | AES-256-GCM 字段级加密；接口永不回显；日志脱敏过滤器 |
| 脚本安全 | 仅工单模板可执行（TPL-06）；模板变更留版本与审计 |
| 审计 | 全行为留痕、只读、分区保留 |

## 9. 关键技术风险与预案

<!-- v2.2 变更: 风险#2 "500台并发SSH" → "大量并发步骤" -->

| 风险 | 预案 |
| --- | --- |
| Ansible 退出码语义随版本变化 | 固定作业主机 Ansible 版本基线（≥2.14）；仅凭进程退出码判定整体成败（不解析 PLAY RECAP），版本升级时需回归验证 |

| MySQL 审计表膨胀 | 按月分区 + DROP PARTITION 清理 |
