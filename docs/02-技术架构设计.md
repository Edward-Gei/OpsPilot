## 1. 技术选型总览

| 层 | 选型 | 版本基线 | 说明 |
| --- | --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Ant Design Vue + Vite + Pinia + Vue Router | Vue 3.4+ / antdv 4.x | SPA，Nginx 托管静态资源并反代 API/WS |
| 后端 API | Python + FastAPI + Uvicorn | Python 3.11+ / FastAPI 0.11x | 异步框架，自动生成 OpenAPI 文档 |
| ORM / 迁移 | SQLAlchemy 2.x（async）+ Alembic | — | MySQL 驱动 asyncmy |
| 执行引擎 | 自研 asyncio Worker + asyncssh | — | 独立进程，见 §4；不采用 Celery（长连接交互式作业不适配） |
| 数据库 | MySQL | 8.0 | utf8mb4，业务数据 + 审计 + 执行元数据 |
| 缓存/队列/通道 | Redis | 7.x | 任务队列、日志 Pub/Sub、运行时控制信号、JWT 吊销、登录失败计数 |
| 定时任务 | APScheduler（内嵌于 Worker） | — | 审计清理、通知重试扫描 |
| 认证 | python-jose(JWT) + passlib(bcrypt) + pyotp(TOTP) + ldap3 + Authlib(OIDC) | — | 认证源可插拔 |
| Excel | openpyxl | — | 导入/导出 |
| 部署 | Docker Compose（单机） | Compose v2 | 内网离线可部署（镜像预拉取/私有仓库） |

**关键取舍说明**

1. **不用 Celery/RQ**：作业是长时运行、需要中途"停止/继续"、实时回传日志的交互式任务，Celery 的任务模型（短任务、结果回调）不匹配；自研 asyncio Worker 用 `asyncssh` 天然支持数百并发 SSH 会话，控制信号走 Redis，模型更简单直接。
2. **日志存文件、元数据存 MySQL**：单工单 500 台 × 多步骤的输出若全进 MySQL 会造成大表；日志按 `执行ID/步骤ID/主机ID` 落盘（共享卷），MySQL 只存状态与摘要；前端实时展示直接长轮询 REST 读文件增量（WebSocket 已弃用，见 §4.3），状态事件回放走 Redis。
3. **API 与 Worker 分进程**：执行高峰不影响 Web 请求；单机 Compose 内以两个容器部署，共享代码库。

## 3. 认证与权限架构

### 3.1 认证流水线

```
登录请求 → AuthProvider 链（local → ldap → oidc 回调）→ 认证成功
        → MFA 策略检查（off/optional/required）
            ├─ 需要 TOTP：签发 mfa_token(短时、仅限 /auth/mfa/*) → 校验 TOTP → 签发正式令牌
            └─ 不需要：直接签发 Access(15min) + Refresh(可配置，默认7d)
```

- **AuthProvider 抽象**：`authenticate(username, password) -> UserIdentity | None`；LDAP/OIDC 首次登录自动建用户（来源标记 + 默认角色，配置项）。
- **OIDC**：授权码模式，`/auth/sso/oidc/login` 重定向至 IdP、`/auth/sso/oidc/callback` 回调后重定向前端 `/login?ticket=xxx`、`/auth/sso/exchange` 用一次性 ticket 换正式令牌（复用三态登录出口，受 MFA 策略约束）、`/auth/sso/options` 供登录页判断是否展示 SSO 入口；按 `sub/email` 映射本地用户，首登自动建用户。
- **令牌管理**：JWT 无状态校验；登出/重置密码时将 Refresh 的 `jti` 写入 Redis 吊销集合（TTL=剩余有效期）；Access 短时效自然过期。
- **个人访问密钥通道**：`get_current_user` 识别 Bearer 凭证的 `opsp_` 前缀——命中则走 `api_token` 表 SHA-256 哈希查表鉴权（过期/账号状态校验，`last_used_at` 60 秒节流更新），否则走 JWT 解码；密钥通道请求打 `api_token_auth` 标记，密钥管理接口（`/user/tokens`）据此拒绝密钥自身调用（防自我繁殖）。
- **登录保护**：失败计数存 Redis `login:fail:{username}`，超限锁定（写 DB 锁定字段 + 审计）。

### 3.2 RBAC 鉴权

- 权限点常量表（代码内枚举 + 初始化写库），角色-权限、用户-角色多对多。
- FastAPI 依赖注入实现：`require_perm("ticket:approve")`；用户权限集合登录时计算并缓存在 Redis（角色变更时失效）。
- 前端按权限点控制菜单/按钮显隐；后端为最终裁决。
- 聚合类接口（工作台概览 `/dashboard/summary`、全局搜索 `/search`）不挂独立权限点：登录即可调用，接口内部按调用者权限集合动态裁剪返回段（无权段为 null），避免为跨模块只读聚合新增权限点。

### 3.3 敏感数据加密

| 数据 | 方案 |
| --- | --- |
| 用户密码 | bcrypt（cost 12） |
| SSH 凭据（密码/私钥）、MFA secret | AES-256-GCM，主密钥 `SECRET_ENCRYPT_KEY` 来自 .env（32 字节 base64）；密文格式 `nonce + ciphertext + tag`，字段级加密 |
| JWT 签名 | HS256，`JWT_SECRET_KEY` 支持配置双密钥轮换（新签旧验） |

## 4. Pipeline 执行引擎（核心）

### 4.1 数据流与生命周期

```
工单审批通过（或免审提交）
  │ API: 工单→queued（排队中），创建 execution + steps + step_hosts 记录（全部 pending）
  │      XADD ops:exec:queue {execution_id}
  ▼
Worker 调度器（Redis Stream 消费组，单机可多协程消费；认领即 XACK，工单/execution→running）
  │ 逐步骤串行调度：step[i] 开始 → 渲染模板参数 → 按类型分派
  ▼
┌─ Shell 执行器 ────────────────────────────────────────────────┐
│ 主机列表按「分批」切片；批内 asyncio.Semaphore(并发数) 控制；     │
│ 全局信号量(默认50)限制平台总 SSH 并发；                          │
│ asyncssh 连接目标主机 → 上传渲染后脚本至 /tmp → 执行 → 流式读输出 │
└──────────────────────────────────────────────────────────────┘
┌─ Ansible 执行器 ──────────────────────────────────────────────┐
│ 生成 inventory(目标主机+连接变量) 与 playbook/ad-hoc 参数文件     │
│ → SFTP 上传到作业主机临时目录 → 执行 ansible-playbook/ansible    │
│ → 流式读 stdout 推日志 → 解析 PLAY RECAP 得到逐主机结果          │
│ → 清理临时目录                                                 │
└──────────────────────────────────────────────────────────────┘
  │ 每行输出：写本地日志文件 + PUBLISH ops:log:{execution_id}
  │ 主机/步骤状态变更：写 MySQL + PUBLISH ops:event:{execution_id}
  ▼
步骤全部完成 → 按失败策略决定进入下一步骤 / 中断
全部步骤完成 → execution 汇总 → 按终态映射表更新工单 → 投递通知事件 → 审计
```

> **概念澄清**：「作业主机」= Ansible 控制节点/执行机（替平台执行 playbook 的机器），≠ CMDB「目标主机」（被操作对象）。作业主机为全局单实例，管理员在系统设置页配置（`ansible.job_host`：host/port/credential_id/workdir + 连通性测试），两者不得混用同一配置入口；V1 不做多台管理/分组/主备。

### 4.2 执行控制实现

| 操作 | 触发方 | 实现机制 |
| --- | --- | --- |
| 并发数 | 工单执行策略 | 批内 `asyncio.Semaphore(concurrency)` |
| 分批 + 批间确认 | 执行策略 | 批完成后若开启"批间暂停"，step 置 `paused`，等待控制信号 |
| 超时 | 执行策略/模板 | `asyncio.wait_for` 单机级；超时置 `timeout` 并按失败策略处理 |
| 失败中断 | 执行策略 | 批结束检查失败数：`fail_fast=true` 时跳过剩余主机（`skipped`）并中断后续步骤 |
| 暂停 pause | 用户（API）/ 批间暂停策略 | 仅 running：写 `ops:ctrl:{eid}=pause` 并 PUBLISH；调度器检查点停止派发后续目标，在跑目标跑完（不打断）后 execution/工单置 `paused`；批间暂停策略自动进入同一状态 |
| 恢复 resume | 用户（API） | 仅 paused：写 `ops:ctrl:{eid}=resume`，调度器从停住处继续派发剩余目标（含批间暂停放行） |
| 中止 abort | 用户（API） | queued/running/paused：写 `ops:ctrl:{eid}=abort`；停止派发，在跑目标等待完成（默认不打断），未派发目标置 `skipped`；execution 置 `terminated`，工单置 `interrupted(user_abort)` |
| 强制中止 force-abort | 用户（API） | running/paused：在中止基础上对在跑目标 `conn.close()` 强杀（best-effort），目标置 `terminated`；高风险操作，独立审计 |
| 撤销 cancel | 用户（API） | 仅「审批中」且模板允许撤回，纯状态机流转，不进队列，工单置 `cancelled` |

- **调度器检查点**（信号响应位置）：① 认领消息开跑前（覆盖 queued 期间下发的信号）；② 每个主机派发前；③ 每批结束后；④ 每步骤开始前。不依赖 queued 瞬间窗口。
- **终态映射**（execution → 工单）：`success→success`；`failed→failed`（含主机级 timeout 聚合，详情按主机标注）；`terminated→interrupted(user_abort)`；`interrupted→interrupted(system_crash/worker_lost)`；主机级 `skipped` 为目标级标记不影响工单终态。
- **ACK 时机**：Worker 认领消息、execution queued→running 的同一时刻立即 XACK，使 queued/running 两阶段崩溃可区分。
- **崩溃恢复（三分支）**：Worker 启动时——① Stream pending 未 ACK 消息（queued 阶段崩溃）用 `XAUTOCLAIM` 重新认领正常重试（尚未执行过命令，重跑安全），仅 `delivery_count` 超阈值（默认 3）才 ACK 丢弃并置 `interrupted(worker_lost)`；② DB 中 `running` 的 execution（已 ACK 后崩溃）置 `interrupted(system_crash)`，主机状态保留现场；③ `paused` 的 execution 调度上下文已丢失（V1 不承诺断点续跑）同样置 `interrupted(system_crash)`。工单同步置 `interrupted` 并落 `interrupt_reason`；崩溃恢复写系统事件审计（`worker_crash_recovered`，含 worker_id/execution_id/ticket_id/reason）并通知提交人与 admin（走通知集成 + 系统事件日志，V1 不引入告警中心）。

### 4.3 实时日志通道（长轮询；WebSocket 已弃用）

```
Worker ──XADD──► Redis(ops:event:{eid} 事件列表) ◄──读取── API /events 长轮询 ──► 浏览器
   └──append──► 日志文件 /data/logs/{eid}/{step}/{host}.log ◄──读取── API /logs 增量 ──► 浏览器
```

- **状态事件**：前端 `GET /executions/{eid}/events?since_seq=` 长轮询循环（服务端有新事件立即返回，否则挂起至 30s；挂起前归还 DB 连接避免连接池耗尽），`finished=true` 结束轮询。
- **实时日志**：前端每 2s `GET /executions/{eid}/logs?offset=` 按行偏移增量拉取追加（Jenkins 式尾随）；切换主机即重置偏移重拉，无订阅状态。
- **WS 弃用说明（2026-07）**：原 `/ws/executions/{eid}?token=` 网关因切换目标主机后订阅失效导致日志无法实时更新，且断线重连/令牌过期链路复杂，已摘除注册；代码保留在 `app/api/ws_deprecated.py`，回切需恢复 `main.py` 注册与 nginx `/ws/` 代理。Worker 侧 `ops:log:{eid}` Pub/Sub 推送保留（与落盘同在 100ms 聚合链路，开销可忽略，当前无消费方，回切 WS 时直接复用）。
- 日志文件随审计保留策略同周期清理。

### 4.4 模板渲染与安全

- 参数渲染用 Jinja2 **沙箱环境**（SandboxedEnvironment），仅允许工单参数与内置变量（`ticket_id`、`app_name`、`host_ip` 等）。
- 工单提交时固化五重快照：主机清单、步骤脚本内容、审批节点、执行策略、模板版本 → 存入工单，审批人看到的即最终执行的。
- 凭据仅在 Worker 进程内存中解密使用，不落日志、不进 API 响应。

## 5. 通知与审计架构

### 5.1 通知（异步、可插拔）

```
业务事件(审批提醒/通过/驳回/执行成功/失败)
  → notify_service.emit(event, payload)  # 写 notification_record(pending) + XADD ops:notify:queue
  ├─ 站内信（NOTIFY-06）：同事务解析收件人用户名 → 每人写一行 user_notification
      （不受渠道启用/事件映射影响；顶栏铃铛 30s 轮询未读数消费）
  → Worker 通知分发器：按事件-渠道映射取启用渠道 → 并发发送
      ├─ EmailChannel(SMTP)  ├─ WebhookChannel(HMAC-SHA256 签名头)  ├─ TeamsChannel(Incoming Webhook Card)
      └─ 预留：DingTalk/Feishu/WeCom（实现 NotifyChannel 抽象即接入）
  → 失败重试：指数退避(1m/5m/15m，默认3次)，APScheduler 扫描 pending/failed
  → 结果回写 notification_record
```

`NotifyChannel` 抽象：`send(event, rendered_content, config) -> Result`；渠道配置存 DB（管理员全局一份），敏感项（SMTP 密码）字段级加密。

### 5.2 审计

- **写入路径**：service 层显式调用 `audit.log(actor, module, action, target, result, detail)`；登录/登出等在认证流程内嵌。异步落库（后台任务队列，避免阻塞请求），进程退出前 flush。
- **不可篡改**：应用层无 UPDATE/DELETE 接口；MySQL 账号对 `audit_log` 表可只授予 INSERT/SELECT（部署脚本可选强化）。
- **保留与清理**：Worker 内 APScheduler 每日按 `AUDIT_RETENTION_DAYS` 删除过期分区数据；`audit_log` 按月 RANGE 分区，清理即 DROP PARTITION，避免大表 DELETE。
- **导出**：查询条件透传，服务端流式生成 CSV/Excel（限制单次导出上限，如 10 万行）。

## 6. 性能与容量设计

| 目标 | 设计应对 |
| --- | --- |
| 1000+ 用户 | API 容器 uvicorn 启动（可按需扩多 worker）；权限集合 Redis 缓存；列表接口全部分页 + 索引覆盖 |
| 1000+ 主机 / 单工单 ≥500 台 | 全局 SSH 并发信号量（默认 50，可配）；step_hosts 批量写入；状态更新按批聚合提交 |
| 实时日志高吞吐 | 日志不进 MySQL；Pub/Sub 每主机限速聚合（100ms 合并推送）；WS 单连接订阅单 execution |
| 列表 P95 < 500ms | 关键查询建复合索引（见数据库设计）；审计按月分区 |
| 单点故障 | V1 接受单机；数据卷持久化 + `mysqldump` 定时备份脚本（deploy 提供 cron 示例） |

## 7. 部署架构（Docker Compose）

```yaml
# deploy/docker-compose.yml 拓扑（示意）
services:
  nginx:    # 对外唯一入口 NGINX_HTTP_PORT(默认8080)→80；静态资源 + /api /ws /healthz 反代
  api:      # backend 镜像，ENTRYPOINT 脚本(RUN_MIGRATIONS=1 执行 alembic upgrade head) + CMD=uvicorn app.main:app
  worker:   # 同一 backend 镜像，CMD=python -m app.worker_main（RUN_MIGRATIONS=0）
  mysql:    # 8.0，卷 mysql-data；init SQL 建库
  redis:    # 7，开启 AOF，卷 redis-data
volumes: mysql-data, redis-data, exec-logs(api 与 worker 共享)
networks: 内部 bridge，仅 nginx 暴露端口
```

- **配置**：全部经 `.env` 注入（数据库、Redis、JWT/加密密钥、审计保留天数、SSH 全局并发、SMTP 等）；`.env.example` 为唯一配置清单来源。
- **初始化**：api 容器启动时（RUN_MIGRATIONS=1）先执行 `alembic upgrade head`，再在应用 lifespan 内幂等执行种子数据（权限点/内置角色/admin 初始账号，首登强制改密）；worker 依赖 api 健康后启动，天然避免并发迁移。
- **内网离线**：镜像在有网环境构建后 `docker save/load` 或推送内网私有仓库；前端构建产物打入 nginx 镜像。
- **健康检查**：各服务 healthcheck；api `/healthz`（含 DB/Redis 探活）。

## 8. 安全设计清单

| 项 | 措施 |
| --- | --- |
| 传输 | 内网可 HTTP；nginx 预留 TLS 配置块（自签/企业 CA） |
| 注入 | ORM 参数化；Pydantic 严格校验；模板渲染 Jinja2 沙箱 |
| XSS/CSRF | 前端默认转义；JWT 走 Authorization 头（非 Cookie），CSRF 面收敛 |
| 越权 | 全接口 `require_perm`；对象级校验（如仅创建人可撤销工单） |
| 凭据 | AES-256-GCM 字段级加密；接口永不回显；日志脱敏过滤器 |
| 脚本安全 | 仅工单模板可执行（TPL-06）；模板变更留版本与审计 |
| 审计 | 全行为留痕、只读、分区保留 |

## 9. 关键技术风险与预案

| 风险 | 预案 |
| --- | --- |
| Ansible 输出解析（PLAY RECAP）随版本变化 | 固定作业主机 Ansible 版本基线（≥2.14）；解析器容错 + 无法解析时以进程退出码判定整体成败 |
| 500 台并发 SSH 的文件描述符/内存压力 | 全局并发上限 + ulimit 配置写入 compose；压测项列入测试计划 |
| WS 长连接经 Nginx 断连 | `proxy_read_timeout` 调大 + 心跳 ping/pong；前端自动重连 + 长轮询降级 |
| Worker 崩溃丢任务 | Redis Stream 消费组 + 启动恢复扫描（§4.2） |
| MySQL 审计表膨胀 | 按月分区 + DROP PARTITION 清理 |
