## 2. 服务拓扑

```text
浏览器
   | HTTP :8080（生产可由外部 TLS 终止）
   v
Nginx（静态资源、/api 反代、/healthz）
   |
   +--> API（FastAPI :8000） --> MySQL 8
   |                         \-> Redis 7
   |
   +--> Worker（独立进程） --> Redis 队列/控制/事件
                              |
                              +--> SSH --> 作业主机 workspace
```

Compose 服务职责：

- `nginx`：提供前端构建产物，反向代理 `/api/`，只暴露 `${NGINX_HTTP_PORT:-8080}`。
- `api`：加载配置、执行迁移和种子、提供 REST API、读取执行日志文件。
- `worker`：消费执行队列，执行步骤、写日志、发送通知、维护审计分区。
- `mysql`：业务数据库，使用 `mysql-data` 卷。
- `redis`：队列和缓存，启用 AOF，使用 `redis-data` 卷。

API 和 Worker 共享 `exec-logs` 卷。MySQL、Redis 和 API 不映射宿主端口；外部只访问 Nginx。

## 4. 认证、权限和加密

### 4.1 认证流水线

本地登录校验 bcrypt 密码；LDAP 和 OIDC 通过对应 Provider 认证并创建/加载用户。成功登录根据 MFA 策略返回正式令牌或临时 `mfa_token`。Access Token 携带用户身份和权限读取结果，Refresh Token 使用 jti 记录并支持吊销。

个人访问密钥以 `opsp_` 前缀生成，数据库只保存哈希；Bearer 访问密钥不能管理 `/user/tokens`，避免自我创建密钥。

### 4.2 RBAC

路由使用 `require_perm` 检查 30 个权限点；用户可有多个角色，权限取并集，Redis 缓存权限并在角色矩阵变化时清理。模板可见范围使用角色 ID 数组，空数组表示所有具有 `ticket:write` 的角色。

### 4.3 敏感数据

- 密码：bcrypt cost 12。
- SSH 凭据和 MFA secret：AES-256-GCM，密钥来自 `SECRET_ENCRYPT_KEY`；未配置时从 JWT 密钥派生并告警。
- JWT：由 `JWT_SECRET_KEY` 签名；密钥不得进入仓库或日志。
- API Token：数据库仅保存 SHA-256；通知渠道 secret 只在服务端解密。

## 5. 模板、工单和快照

工单模板保存入口参数、动态生成、作业主机、流程引用、撤回、通知和可见角色；流程模板保存步骤、步骤前审批角色和执行策略。模板服务在保存时校验名称唯一、作业主机启用、流程模板启用、角色存在和参数定义合法。

创建工单时读取两类模板并创建完整快照：作业主机连接信息、流程名称、执行策略、步骤脚本/超时/审批角色、参数定义和结果、动态生成结果、撤回开关。执行和详情只读快照，模板后续编辑不会影响历史工单。

动态参数先调用 `POST /tickets/prepare` 在作业主机执行，短期保存 `prepare_id`、固定值和候选项；正式提交时消费并校验，失败或过期不能绕过校验。

待审批分配、流转、驳回和撤回后，为受影响用户写入 Redis 用户级待办事件：`todo.changed`。每个用户维护独立递增序号和可回放列表（最多 2000 条，保留 3 天）；前端以 `GET /tickets/todo/events?since_seq=` 最长 30 秒的长轮询接收事件，并在收到事件后刷新待办计数。客户端必须直接赋值服务端返回的 `last_seq`，不能取最大值；当 Redis 过期导致客户端游标大于当前序号时，接口返回单条合成 `todo.changed` 重同步事件和较小的 `last_seq`。接口无新事件时返回空列表和原序号，长轮询期间不占用数据库连接。

## 6. Worker 执行引擎

### 6.1 生命周期

```text
工单提交/审批通过
  -> 创建 execution 和 execution_step
  -> XADD Redis 执行队列
  -> Worker 认领并 ACK
  -> queued -> running -> paused/running -> success/failed/terminated/interrupted
  -> 同步更新工单状态和通知
```

一个工单对应一个执行实例；步骤严格按顺序执行。`fail_fast=true` 时步骤失败会将未执行步骤置为 `skipped`；超时单独记录 `timeout` 步骤结果。

### 6.2 执行控制

控制信号写入 Redis，Worker 在步骤开始、输出循环和步骤结束等检查点读取：

| 操作 | 行为 |
| --- | --- |
| pause | 当前步骤完成后暂停，不进入下一步 |
| resume | 从暂停位置继续 |
| abort | 当前步骤尽量完成后终止后续步骤，工单为 `interrupted/user_abort` |
| force-abort | 尽力终止作业主机当前进程，记录高风险审计 |

Worker 重启时，排队消息可重新认领；无法恢复的运行中/暂停执行标记为 `interrupted/system_crash`，队列长期无人认领标记为 `worker_lost`。

### 6.3 SSH 执行

Worker 使用作业主机绑定凭据建立 `asyncssh` 连接，在 `workdir` 下执行 Shell 或 Playbook。脚本输出实时写入 `exec-logs/<execution_id>/step_<step_order>.log`；退出码和摘要写入 MySQL。日志不写入数据库正文，避免大输出膨胀业务表。

## 7. 实时日志和事件

事件接口 `GET /api/v1/executions/{id}/events` 使用 REST 长轮询；日志接口 `GET /api/v1/executions/{id}/logs` 使用 `step_order`、`offset`、`limit` 读取文件行。前端以事件更新状态，以约 2 秒间隔增量读取日志并合并展示。

Worker 同时向 Redis 发布执行事件，API 长轮询在超时或收到事件时返回；日志文件是历史回看的持久来源。Nginx `/api/` 的读取超时设置为 120 秒。

## 8. 通知架构

`notify_service.emit` 根据工单模板通知规则解析收件人，按事件-渠道映射创建 `notification_record`，并写入站内信。通知队列用于加速触达，Worker 每 30 秒扫描 `pending` 记录作为可靠兜底。

Email 发送标题和正文；Webhook 发送渲染后的 JSON body 并支持 HMAC 签名；Teams 发送渲染后的 Adaptive Card JSON。模板按渠道和事件保存，保存和最终渲染都必须通过 JSON 校验。

发送前使用原子状态认领 `pending -> sending`，防止队列触发与定时扫描重复发送。网络类失败按 60/300/900 秒退避，最多三次；确定性失败直接置 `failed`。密码重置邮件即使普通 Email 渠道关闭也按安全邮件路径投递，失败原因只写内部审计。

## 9. 审计和定时任务

业务路由通过 `audit.log` 写入异步审计队列；Worker 的审计写入器批量落库。审计表按月分区，只允许追加和查询，导出动作本身也写审计。定时任务预建未来分区并按 `AUDIT_RETENTION_DAYS` 删除过期分区。

## 10. 数据和部署配置

- `RUN_MIGRATIONS=1` 仅 API 执行 Alembic；Worker 设置为 `0`。
- API 健康后 Worker 和 Nginx 才启动。
- `.env.example` 是配置变量唯一模板，包含数据库、Redis、JWT、字段加密、令牌、密码重置、审计、日志、并发、CORS 和 DEBUG 配置。
- `exec-logs` 卷保存执行日志；`mysql-data` 保存业务数据；Redis 数据可重建。

## 11. 安全边界

生产环境只暴露 Nginx，关闭 DEBUG，限制 `.env` 权限。密码重置接口所有分支统一公开响应；令牌只保存哈希并原子单次消费。凭据和 MFA secret 不出现在 API 响应、快照正文、日志或审计详情中。导入、导出、强制中止、角色和渠道配置均经过独立权限点控制。
