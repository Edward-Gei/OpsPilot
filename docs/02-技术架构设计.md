## 2. 服务拓扑

```text
浏览器 -- HTTP :8080 --> Nginx -- /api/ --> API（FastAPI :8000）
                         |                  |       |
                         +-- 静态资源       v       v
                                          MySQL   Redis
                                            ^       ^
                                            |       |
                                      Worker（独立进程）
                                            |
                                            +-- SSH --> 作业主机
                                            +-- DNS / 配置平台 / 通知渠道

                    database-executor -- 平台 MySQL：任务/配额/结果/独立审计
                            |
                            +-- 目标 MySQL / PostgreSQL / MongoDB / ClickHouse / Redis
```

Compose 服务职责：

- `nginx`：提供前端构建产物，反向代理 `/api/`，只暴露 `${NGINX_HTTP_PORT:-8080}`；不代理 Worker。
- `api`：加载配置、执行迁移和种子、提供 REST API、读取执行日志文件；预生成参数时直接连接作业主机，发现及手动 DNS 操作等请求直接访问外部平台。
- `worker`：消费执行队列，执行步骤、写日志、发送通知、维护审计分区；独立轮询数据库中的 DNS 绑定和应用配置任务。
- `database-executor`：独立认领数据库查询任务，访问目标实例并处理停止、恢复和到期清理；可增加副本，配额通过平台 MySQL 协调。
- `mysql`：业务数据库，使用 `mysql-data` 卷。
- `redis`：队列、控制、事件、缓存和临时认证状态，启用 AOF，使用 `redis-data` 卷。

API 和 Worker 共享 `exec-logs` 卷，数据库执行器不挂载该卷、不开放服务端口。MySQL、Redis 和 API 不映射宿主端口；外部只访问 Nginx，生产可由外部网关终止 TLS。拓扑依据为 [Compose](../deploy/docker-compose.yml)、[Nginx](../deploy/nginx.conf)、[Worker 入口](../backend/app/worker_main.py)和[数据库执行器入口](../backend/app/database_executor_main.py)。

## 4. 认证、权限和加密

### 4.1 认证流水线

本地登录校验 bcrypt 密码；LDAP 和 OIDC 通过对应 Provider 认证并创建/加载用户。成功登录根据 MFA 策略返回正式令牌或临时 `mfa_token`。JWT 携带 `sub`、`username`、`scope`、`jti`、`iat`、`exp`，Access/Refresh 正式令牌另含首次登录的 `session_exp`，不携带权限集合；请求先验证用户有效状态，再由 RBAC 服务读取权限。无 `session_exp` 的旧正式令牌须重新登录。实现见[令牌生成](../backend/app/core/security.py)与[请求依赖](../backend/app/core/deps.py)。

前端完成登录验证并加载用户信息后，等待目标路由导航完成才提示“登录成功”，导航失败则明确提示。旧页面遇到动态模块或 CSS 预加载失败时，以无缓存请求读取 `/index.html`；仅确认可信同源模块入口版本已变化，才自动恢复一次至合法站内原目标。恢复检查仅对当前导航有效；新导航或同页重新认证会使旧检查静默失效，避免覆盖用户后续操作。`sessionStorage` 按入口版本组合记录恢复标记以防循环，该标记不保存认证票据、令牌或目标查询参数；同版资源错误、普通导航错误和版本检查失败均不触发刷新。认证、MFA、跨窗口会话同步和固定会话截止策略保持不变。

Refresh Token 的吊销范围按入口不同：登出吊销当前 jti，邮箱重置成功吊销该用户全部 Refresh，`POST /auth/refresh` 签发新对后吊销旧 jti；本人改密（含 40105 强制改密）和管理员重置他人密码都不吊销既有令牌，Access Token 本就不即时失效。刷新流程是“先查吊销表、再写吊销”，两步之间无原子保障，也没有重放检测：同一 Refresh 被并发使用会各自签发一组新令牌。描述这些行为时不能笼统写成“改密即失效全部会话”。

LDAP 以配置的服务账号搜索用户 DN，再用用户口令重绑定校验；`user_filter` 的 `{username}` 由[认证源](../backend/app/auth_providers/ldap.py)直接字符串替换，未做 LDAP 过滤器转义，含元字符的登录名可扩大搜索范围，但通过校验仍需要目标条目的正确口令。LDAP 与 OIDC 首次登录都自动建用户并授予 `ldap.default_role` / `oidc.default_role`，配置缺失时回退 `ops` 角色，角色编码不存在时静默不授予任何角色。`user.username` 全局唯一：OIDC 先查同名再追加 `_{sub[:8]}`（追加结果不再复检），LDAP 只在 `source=ldap` 范围内查找，因此与本地或 OIDC 账号同名的首登会在写入时触发唯一键冲突而非业务拒绝。LDAP 搜索和重绑定阶段的异常（服务不可达、过滤器非法）按认证失败处理；首登写库异常不在该捕获范围内。

个人访问密钥以 `opsp_` 前缀生成，数据库只保存哈希；Bearer 访问密钥不能管理 `/user/tokens`，避免自我创建密钥。

### 4.2 RBAC

路由使用 `require_perm` 检查 [46 个权限点](./04-API设计.md#12-权限点全集)；用户可有多个角色，权限取并集，Redis 缓存权限并在角色矩阵变化时清理。域名管理使用独立的 `domain:read`、`domain:write` 和 `domain:delete`；模板可见范围使用角色 ID 数组，空数组表示所有具有 `ticket:write` 的角色。数据库查询还须检查角色的显式实例授权，管理权限和应用关联均不自动授予查询权。

### 4.3 敏感数据

- 密码：bcrypt cost 12。
- SSH 凭据和 MFA secret：AES-256-GCM，密钥来自 `SECRET_ENCRYPT_KEY`；未配置时从 JWT 密钥派生并告警。
- JWT：由 `JWT_SECRET_KEY` 签名；密钥不得进入仓库或日志。
- API Token：数据库仅保存 SHA-256；通知渠道 secret 只在服务端解密。
- DNS 服务商认证继续复用凭据管理的加密字段；域名模块只保存 `credential_id`，响应、导出、日志和审计不回传认证明文。

## 5. 模板、工单和快照

工单模板保存入口参数、动态生成、作业主机、流程引用、撤回、并发控制、适用应用、通知和可见角色；流程模板保存步骤、步骤前审批角色和执行策略。模板服务在保存时校验名称唯一、作业主机启用、流程模板启用、角色存在和参数定义合法。

创建工单时冻结流程名称、执行策略、步骤脚本/超时/审批角色、参数定义和结果、动态生成结果、撤回开关，以及作业主机展示信息和密钥引用。步骤执行读取工单快照，但连接时按 `job_host_id` 重新读取当前作业主机与其绑定凭据，脚本密钥按 ID 读取当前值；通知事件读取当前工单模板的 `notify_rules`。因此快照不等于所有运行时依赖都已冻结。依据见[工单服务](../backend/app/services/ticket_service.py)与 [Pipeline](../backend/app/engine/pipeline.py)。

提交页通过 `POST /tickets/prepare` 在作业主机执行生成脚本，结果保存十分钟。`POST /tickets` 的 `prepare_id` 当前可选；提供时检查模板 ID、过期和消费标记并校验候选选择，未提供时仍可从 `params` 取得生成参数。预生成服务未复用正式提交的模板可见性校验，消费时也未对照原始输入或使用条件更新锁定消费，不能将页面步骤顺序写成强制、原子的服务端预生成保障。具体边界见[模板参数说明](./06-模板管理与流程模板设计.md#42-动态参数预生成)。

待审批分配、流转、驳回和撤回后，为受影响用户写入 Redis 用户级待办事件：`todo.changed`。每个用户维护独立递增序号和可回放列表（最多 2000 条，保留 3 天）；前端以 `GET /tickets/todo/events?since_seq=` 最长 30 秒的长轮询接收事件，并在收到事件后刷新待办计数。客户端必须直接赋值服务端返回的 `last_seq`，不能取最大值；当 Redis 过期导致客户端游标大于当前序号时，接口返回单条合成 `todo.changed` 重同步事件和较小的 `last_seq`。接口无新事件时返回空列表和原序号，长轮询期间不占用数据库连接。

## 6. Worker 执行引擎

### 6.1 生命周期

```text
工单提交/审批通过
  -> 创建 execution 和 execution_step
  -> XADD Redis 执行队列
  -> Worker 认领并 ACK
  -> queued -> running -> paused/running -> success/failed/terminated/interrupted
  -> 同步更新工单状态和通知
```

一个工单对应一个执行实例；步骤严格按顺序执行。`fail_fast=true` 时当前实现停止推进，但不会统一将后续 `pending` 步骤改为 `skipped`。当前作业主机 Shell/Playbook runner 超时返回 `failed` 并保存超时摘要；模型及旧主机 runner 中的 `timeout` 不代表当前主链会产生独立超时状态。

### 6.2 执行控制与恢复边界

API 将控制信号写入 Redis 并发布；Worker 的 watcher 每 0.5 秒轮询信号并更新内存标志，Pipeline 在步骤边界、runner 在运行循环检查这些标志：

| 操作 | 行为 |
| --- | --- |
| pause | 当前步骤完成后暂停，不进入下一步 |
| resume | 从暂停位置继续 |
| abort | 当前步骤尽量完成后终止后续步骤，工单为 `interrupted/user_abort` |
| force-abort | 尽力断开已注册的 SSH 会话，不保证远端所有派生进程已终止；记录高风险审计 |

Worker 启动时把数据库中的 `running/paused` 执行标为 `interrupted/system_crash`，不自动重跑脚本；另检查 Redis 消费组待确认列表（PEL），认领未超重试阈值的消息，超阈值分支使用 `worker_lost`。这不是按排队时长扫描全部 `queued` 执行。

撤回与执行状态写入之间没有行锁或状态条件保护：[工单服务](../backend/app/services/ticket_service.py)只把仍为 `queued` 的执行置为 `cancelled` 并释放该执行占有的同模板并发锁，而 Pipeline 在读取到 `queued` 之后直接把执行和工单写为 `running`。若撤回提交落在这两次写入之间，状态会被覆盖回执行中，已释放的并发占用也不会重新获取。这是静态阅读得到的竞态窗口，未经并发验收。

执行消息在业务事务提交前 `XADD`，Worker 认领即 ACK；Pipeline 最多十次短暂重读只缓解提交可见性竞态。入队失败或 ACK 后、状态落库前崩溃仍可能留下无队列消息的 `queued` 执行，当前没有对应的全表补发兜底。该边界不同于有数据库 `pending` 扫描的通知任务；依据见 [Worker](../backend/app/worker_main.py)、[Pipeline](../backend/app/engine/pipeline.py) 和[恢复逻辑](../backend/app/engine/recovery.py)。

### 6.3 SSH 执行

Worker 使用当前作业主机及绑定凭据建立 `asyncssh` 连接。Shell 通过 `bash -s` 执行，动态参数生成也未显式切换到 `workdir`；Playbook 才在 `workdir/opspilot/exec_<id>_step_<order>` 临时目录执行 `ansible-playbook -i localhost, -c local`，结束后尽力清理。两类步骤按退出码判断，不按 PLAY RECAP 聚合目标主机结果。

脚本输出实时写入 `exec-logs/<execution_id>/step_<step_order>.log`，退出码和摘要写入 MySQL，日志正文不入库以避免膨胀业务表。脚本密钥通过[运行时载荷](../backend/app/engine/secret_runtime.py)注入：文本密钥文件写入远端随机临时目录并收紧为 `0600`，异常与超时路径在 `finally` 尽力清理；日志摘要在落库前按注入值长度倒序精确替换为 `***`。Shell 步骤走这条链路；Playbook 步骤不构建该载荷，正文按模板原样写入 `workdir` 下的临时文件并以 `ansible-playbook` 读取，日志也不经过上述替换，因此不得宣称密钥不会出现在 Playbook 文件、命令输出或日志中。动态参数生成的参数 JSON 在该载荷存在时经 stdin 前置片段传入（载荷对象恒为真值，预生成调用总是提供），未提供载荷的调用形态才会退化为命令行 `export`。

连接与命令依据见 [Shell runner](../backend/app/engine/ssh_runner.py) 和 [Playbook runner](../backend/app/engine/ansible_runner.py)。当前 SSH 连接使用 `known_hosts=None`，Playbook 命令也关闭主机密钥校验，不能宣称已验证远端主机身份。

## 7. 实时日志和事件

事件接口 `GET /api/v1/executions/{id}/events` 使用 REST 长轮询；日志接口 `GET /api/v1/executions/{id}/logs` 使用 `step_order`、`offset`、`limit` 读取文件行。前端以事件更新状态，以约 2 秒间隔增量读取日志并合并展示。

Worker 同时向 Redis 发布执行事件，API 长轮询在超时或收到事件时返回；日志文件是历史回看的持久来源。Nginx `/api/` 的读取超时设置为 120 秒。

[执行详情页](../frontend/src/views/execution/ExecutionDetail.vue)的读取参数：合并日志流最多保留 20000 行，超出后从最早段头部丢弃并显示省略提示；单次日志请求使用服务端上限 2000 行；某段拉取失败时保留已加载内容并重置该段 `eof`，由下一个 2 秒 tick 重试。事件长轮询客户端超时 40 秒（服务端单次挂起上限 30 秒），异常固定 3 秒后重连；执行进入终态或离开页面即停止全部轮询，终态前额外补拉一轮收尾日志。

事件通道使用 Redis `INCR` 发号、2000 条列表回放和三天键过期，接口在事件列表为空时回传客户端上送的 `since_seq`，不提供[待办通道](./04-API设计.md)那样的合成重同步。前端把本地游标与 `last_seq` 取最大值，因此长时间无事件（例如暂停超过三天）导致键过期后，发号从 1 重新开始，后续事件序号小于客户端游标而不再被消费：页面状态会停在最后一次成功读取，直到下一次轮询从数据库读到终态状态才整体刷新。日志增量拉取不依赖事件序号，不受该边界影响。

[日志通道](../backend/app/engine/logs.py)先写进程内缓冲，每 100 毫秒批量追加文件并发布 Redis 消息；刷盘前已取出该批缓冲，异常只记录警告、不重新入缓冲。因此进程崩溃或文件写入失败可能丢失日志，不能视为无损日志管道；文件写入成功但 Redis 发布失败时仍可通过历史接口读取。

## 8. 通知架构

`notify_service.emit` 根据工单模板通知规则解析收件人，按事件-渠道映射创建 `notification_record`，并写入站内信。通知队列用于加速触达，Worker 每 30 秒扫描 `pending` 记录作为可靠兜底。

Email 发送标题和正文；Webhook 发送渲染后的 JSON body 并附加可选 HMAC 签名头；Teams 通过 Incoming Webhook 发送渲染后的 MessageCard JSON。模板按渠道和事件保存，保存和最终渲染都必须通过 JSON 校验。

[Webhook 渠道](../backend/app/notify/webhook.py)用 `json.dumps(..., ensure_ascii=False)` 计算签名，再通过 HTTPX 的 `json=` 参数另行序列化发送；当前固定的 HTTPX 0.27.2 下，含中文等非 ASCII 字符时两份字节不一致，接收方按原始请求体验签会失败。此差异已用实际渠道代码和离线 MockTransport 复现，尚未修复。Webhook 和 [Teams 渠道](../backend/app/notify/teams.py)仅将 `>=400` 视为失败，未跟随的 3xx 也会返回成功，不能将发送记录成功等同于接收方已处理。

发送前使用原子状态认领 `pending -> sending`，避免队列触发与定时扫描同时发送。网络类失败按 60/300/900 秒退避，最多三次；确定性失败直接置 `failed`。单 Worker 启动时将遗留 `sending` 重置为 `pending`；外部已收到但本地未记成功时可能重发，不是恰好一次投递。

申请密码重置时，[认证服务](../backend/app/services/auth_service.py)要求 Email 渠道启用且 SMTP 配置完整，否则不生成邮件并记录内部原因；已入队的密码重置邮件在[分发器](../backend/app/notify/dispatcher.py)中走安全邮件分支，可不受后来关闭普通渠道开关的影响。这两个阶段不能混为“渠道关闭仍可申请发送”。

## 9. 审计和定时任务

业务通过 `audit.log` 写入所在进程的内存队列，API 和 Worker 各启动自己的批量写入器，并非 API 把审计交由 Worker 统一落库。队列最多 10000 条，每批最多 50 条；队列满或数据库写入失败时会丢弃记录并写日志，不具备持久队列重放保障。实现见[审计写入器](../backend/app/audit/writer.py)。审计表按月分区，业务只追加和查询，导出动作也写审计；Worker 定时预建未来分区并按 `AUDIT_RETENTION_DAYS` 删除过期分区。

## 10. 数据和部署配置

- `RUN_MIGRATIONS=1` 仅 API 执行 Alembic；Worker 和数据库执行器设置为 `0`。
- API 健康后 Worker、数据库执行器和 Nginx 才启动。
- [`.env.example`](../deploy/.env.example) 是部署变量模板；存在默认配置项不代表执行链已使用。当前 Worker 未消费全局并发配置，已实现的是可选的同模板互斥。
- `exec-logs` 卷保存执行日志；`mysql-data` 保存业务数据；`redis-data` 保存队列、控制、事件和临时认证状态，不能全部从 MySQL 重建。
- 真实 MySQL 空库升级与旧库升级须分别验证；当前迁移链的重复加列及历史重建限制见[开发与验收指南](./05-开发与验收指南.md#33-迁移与清理)。

## 11. 安全边界

生产环境只暴露 Nginx，关闭 DEBUG，限制环境文件权限。密码重置申请采用统一公开响应；凭据明文、令牌和配置敏感值不得进入日志、审计或无权响应。不能笼统声明所有 API 永不返回秘密：个人访问密钥创建会一次性返回明文，MFA 绑定会向有权用户返回绑定 secret/URI，应用配置正文受 `secret:read` 控制。权限检查和脱敏须按具体接口验证，不能仅从数据库加密字段推断。

## 12. 域名管理与 DNS 快照

域名模块采用“统一 Zone 快照 + 服务商适配器”结构。适配器统一实现公网 Zone 发现、记录集读取、读取指定记录集以及简单记录集的创建、替换、删除；适配器内部处理 DNSPod、Route 53 和 Google Cloud DNS 的 SDK 字段、分页和异步变更。服务层以 `ZoneRef`、`RemoteRecordSet` 和 `RecordSetDraft` 归一化服务商差异，`provider_meta` 与 `record_key` 仅用于服务端定位，绝不返回客户端。

Route 53 和 DNSPod 使用已有的 `username_password` 凭据类型，Google Cloud DNS 使用已有的 `secret_file` 凭据类型承载 Service Account JSON。服务端按服务商过滤兼容凭据，只在调用适配器期间短暂解密；凭据删除时会检查已绑定 Zone 并拒绝删除。Route 53 写入被接受后，适配器通过 `ListResourceRecordSets` 定向确认目标记录状态，不依赖 `GetChange`；该读取权限也用于快照和远端漂移校验。

绑定前先发现可访问的公网 Zone。提交绑定时 API 只校验凭据并写入 Zone 绑定任务，返回 `202`；Worker 在独立会话中串行处理任务，先发现一次远端 Zone，再逐项拉取已有记录形成快照并持续落库进度。任务使用十分钟租约，子项使用该任务租约的认领令牌；Worker 异常退出后由后续 Worker 重新认领过期任务和未完成子项。任务仅保存凭据 ID 与操作人信息，不保存认证明文。Zone 绑定任务首次发现或快照读取失败时，已知 Zone 仍会保留为 `failed` 空快照，并记录错误摘要；已有 Zone 快照不会被覆盖。后续同步仅由用户手动触发；服务商是事实来源，同步失败或记录写入结果未知时保留最后成功快照并记录错误，用户需手动同步确认。每个 Zone 通过 `operation_token`、`operation_kind` 和 `operation_expires_at` 的条件更新获取两分钟操作租约，避免同步与记录写入并发覆盖。解绑只删除本地 Zone 和记录快照。

可写记录类型为 `A`、`AAAA`、`CNAME`、`MX`、`TXT`、`CAA`、`SRV`，TTL 统一校验 300 至 86400 秒。SOA、NS 与高级路由记录保留在快照中但标为只读。修改或删除会先读取远端记录并与快照比较；发现漂移返回 `40901`，服务商认证、参数拒绝或临时不可用分别映射为业务拒绝或 `50201`。成功写入后立即刷新快照并记录审计。

## 13. 应用配置

“应用配置”是独立菜单，以一个精确远端定位的配置文件为管理对象；CMDB 应用仅作多对多关联，不参与授权。平台实例复用凭据，Apollo、Nacos、Consul 均通过 `backend/app/config_providers/` 的 HTTP 适配器访问。只管理生产配置，发现可多选接入；手工新建会先建立本地草稿，正式版本由审批后的发布生成。

正文、草稿、版本及远端快照使用现有 AES-256-GCM 字段加密；API 根据 `secret:read` 返回原文或脱敏内容。无此权限的结构化编辑用固定占位符保持原敏感值，TEXT 只允许完整替换。审批依据配置文件指定角色的当前成员（或 admin 身份），允许提交人自审，不使用 CMDB 关联推导审批权。审批动作会实时复核成员关系并附加用户启用状态，待办列表只按角色成员关系过滤；由于请求依赖对所有接口强制 `status=active`，这一差异是重复校验，不构成禁用用户仍可见待办的越权。

平台实例连通性测试把失败原因写入实例的探测字段；当连接解析阶段抛出业务错误时，[配置服务](../backend/app/services/application_config_service.py)按字符串截取其 `code`，而业务错误码是整数，实际会转为未捕获的类型错误返回 `50001`，本次失败探测同时随会话回滚不落库。配置文件租约在归档路径同时判断标记与到期时间，导入路径只判断标记非空，未先判空 `operation_expires_at`；现有认领与释放都成对写这两个字段，因此该差异只在数据处于标记有值、到期时间为空的异常状态时才暴露。

接入、同步与发布任务由 Worker 认领并持久化。手动同步发现不同会保留漂移标签，直到再次同步一致、导入远端快照为本地正式版本，或重新发布成功；取消差异视图不修改状态。导入仅更新 OpsPilot，发布在写前比对基线、写后回读；本模块不自动同步、不发漂移通知，也不删除外部资源。平台真实版本验证状态见[兼容性记录](./应用配置平台兼容性记录.md)。

## 14. 数据库管理

数据库管理复用现有认证、角色、凭据加密、系统设置和 MySQL，独立 `database-executor` 访问目标；现有 Worker 继续处理工单和应用配置。需求、数据、API 与验证分别见[PRD §8](./01-产品需求文档PRD.md#8-数据库管理)、[数据库 §11](./03-数据库设计.md#11-数据库管理)、[API §14](./04-API设计.md#14-数据库管理)和[开发与验收 §5](./05-开发与验收指南.md#5-数据库管理开发与验收)。

### 14.1 组件与运行边界

```text
浏览器 -> 现有 API -> 内部 MySQL：台账/授权/持久任务/结果/独立审计
                          ^
             database-executor 多副本 -> 登记的目标数据库入口
```

API 不连接目标，提交返回 202 后由执行器认领，浏览器短请求轮询状态及保存结果；取消同样先持久化。没有额外内部 RPC 或 Redis 数据库任务队列，MySQL 是任务和配额事实来源。应用—实例—承载主机均多对多，原部署主机关系独立；查询范围是角色—实例，应用关系不授权。

台账 Excel 导入在 API 内逐行校验并以短事务写入平台记录，不连接目标。允许按名称更新既有实例，但引擎须保持一致；新名称创建无凭据、停用的待配置实例。导入不修改凭据、角色授权、应用/主机关联、连接选项、探测结果或已有实例启停状态。无凭据实例不能启用，查询、结构读取和连接测试请求会被拒绝并留痕，不访问目标；导出只读取当前筛选的安全台账字段，不包含凭据及查询结果。

生产 Compose 的执行器使用同一后端源码构建、独立入口 `python -m app.database_executor_main`，RUN_MIGRATIONS=0，等待 API 健康；不暴露端口、不固定容器名、不挂工单日志卷。默认每副本 CPU 1、内存 1 GiB、PID 256，停止窗口30秒；运行健康检查读取本进程持久心跳与内部库，不因一个目标认证失败重启组件。内部专属连接池 pool_size=4/max_overflow=0。

### 14.2 只读与适配器

SQLGlot 按 MySQL/PostgreSQL/ClickHouse 方言解析完整输入、递归节点/函数白名单；全部只读后只执行最后一条完整 SELECT，混合或未知语义整段拒绝。账号只读是最终约束，不把含 SELECT 视为天然无副作用。MongoDB/Redis 为严格受控原生结构，不开放任意命令或脚本。

probe 是独立的连接与认证检测路径，仅执行平台固定 SELECT 1 或 ping，不执行用户输入、不设置或校验只读；检测成功不证明账号只读或业务查询权限。SQL、元数据和原生查询继续使用各自的只读事务、输入策略与资源限制。

| 引擎 | 实际驱动与读取路径 | 目标停止依据 |
| --- | --- | --- |
| MySQL | asyncmy SSCursor，读取协议包头前限制分配 | 同 server_uuid、本人连接和唯一查询标记，KILL QUERY 后复核 |
| PostgreSQL | asyncpg 只读事务、有界游标及消息长度护栏 | 地址/端口/postmaster_start、pid/backend_start 与 application_name 相符后取消并刷新活动快照 |
| ClickHouse | httpx 有界 JSONCompactEachRowWithNamesAndTypes 流 | 精确 query_id+user 的 KILL SYNC finished，或 query_log 正向终态记录 |
| MongoDB | PyMongo 正式异步、directConnection、池1/监控保守计量、batchSize=1 | 同 topologyVersion.processId 和唯一 comment，currentOp/killOp 核实 |
| Redis | redis.asyncio 受限 RESP2、GETRANGE 与扫描/范围分页 | 同 run_id、CLIENT ID/唯一name，再精确查询/取消 |

适配器 open/run/batches/stop/close 共用绝对截止时间。close 仅清本地资源，不能代替目标终止证据；关闭失败、代理节点不同、日志尚未落库或控制权限不足均须保留未知事实。ClickHouse 不用 display-name 或 processes 零匹配确认停止；MySQL/PG 客户端连接错误和无官方异常头的代理 HTTP 失败也不算停止。

所有连接只访问登记入口，不自动发现或追随未登记节点。Redis 游标以 HMAC 绑定连接/凭据/DB/key/pattern/type，有效10分钟；签名不替代当前权限。ClickHouse 固定 max_memory_usage=268435456（256 MiB）、max_threads=2，并施加执行/结果/块限制。该限制不代表所有目标数据库的统一资源上限。

### 14.3 任务、配额和恢复

任务按 global→instance→user 锁序在短事务内认领、预留预算和写开始事实；目标网络调用不持有内部事务。全局互斥后的写入/删除引用检查使用当前锁定读，避免 MySQL REPEATABLE READ 旧快照漏看新提交引用。

默认全局20、实例5、用户2任务槽，本地每执行器10；全局/实例/本地保留2/1/1槽给 probe/metadata，不借给普通数据查询。平台/用户队列上限200/10，等待120秒。额度跨所有副本合计，热点已满实例/用户先过滤，不让候选前缀堵住其他实例。

任务槽与物理 socket 分开计量，适配器声明 target_connection_cost/control_connection_cost；Mongo 含池与监控保守按每任务/控制各3 sockets，其余适配器按经验证成本计。控制操作另保留全局2/实例1槽。过期控制租约保留 control_recovering 与物理计量，不能自动归零。

```text
queued -> running -> succeeded / failed
   |          |-> stopping -> cancelled / timed_out（确认后）
   |          |-> recovering（失联/租约过期/停止或清理未确认）
   |-> cancelled / queue_expired / rejected（未执行）
```

5秒心跳、30秒任务租约用于所有权和恢复，不证明目标结束。token/CAS 防旧副本回写，终态与配额一次性结算；未发出任何目标操作的复查失败可 running→rejected，已尝试目标调用不能再称未执行。恢复只核实目标和结算，不重放查询；无法得到可信证据时持续保留占用，可能降低可用容量，需运维核实。

执行先取消并等待本地读取任务、关闭适配器，再发布终态和结果、释放额度。目标已结束但本地或控制连接关闭未确认时仍为 recovering，结果不可读，任务/socket/存储预留保留；不靠租约到期重置未知连接。旧执行器只可为自己的 cleanup token 补记关闭证据，不能用旧任务 token 结算；补证成功后由后续维护核实结算。

### 14.4 有界结果与独立生命周期

执行默认60秒，覆盖连接、操作和读取，排队独立计时；开始处理快照限制，配置变化影响之后开始的任务。结果最多1000行/5MiB，canonical UTF-8 `{columns,rows}` 在加密前计量，重名列保留 ordinal；特殊类型按 API 编码保真。结果构建器仅缓存有界结果，并按约256KiB的 rows-only 块保存，不先全量取得目标结果再裁剪。

manifest/chunks/摘要及终态同事务发布 ready；预留 `2*max_result_bytes+65536`，完成按真实密文载荷收缩。平台1GiB预算为结果载荷及预留，不是整个 MySQL 磁盘上限。真实协议/单值护栏与进程资源限额仍需分别验证，5MiB输出不等于5MiB进程内存。

独立审计直接与业务事务持久化，不依赖通用审计内存队列。原提交、实际操作、prepared参数和结果加密，日志只写ID/受控码；审计含身份、目标及账号安全快照、过程/终态依据，无结果集。结果仅本人并重查当前实例授权，probe 本人凭维护权仅读安全摘要。

结果完成后30分钟失效；历史按 finished_at 默认30天，过期隐藏但未到期结果/活动恢复记录延迟物理删除；审计默认90天，以独立终态事件时间整组清理，不依赖 task 存续，未终态组不清理。维护使用共享租约，单副本执行某次恢复/清理；通用审计365天默认值不变。
