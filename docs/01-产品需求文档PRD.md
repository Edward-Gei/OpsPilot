## 1. 产品概述

### 1.1 产品定位

面向企业内网环境的轻量级自动化运维平台，围绕"**发布工单驱动的作业执行**"核心链路，提供资源管理（CMDB）、作业执行（Shell/Ansible 流水线）、工单中心、安全审计和消息通知能力。

### 1.2 核心业务闭环

<!-- v2.2 变更: 整段重写。模板配置时选定作业主机；工单提交只需选模板+填参；CMDB 退化为资产台账，与执行解耦 -->

```
CMDB 维护主机/应用（资产台账） → 模板管理定义工单模板（作业主机 + 步骤编排(内嵌脚本) + 执行策略 + 审批规则 + 通知规则 + 权限范围）
    → 工单中心选模板填参数提交（标题=模板名，作业主机取模板配置的那台）
    → 模板内审批流依次审批（每模板独立配置，可免审） → 通过后自动执行 Pipeline（所有步骤统一在作业主机上执行，实时日志）
    → 结果通知（邮件/Webhook/Teams） → 全程审计留痕
```

**关键链路**：模板定义时选择"作业主机"（类 Jenkins agent 的通用执行节点）→ 提交工单时直接取模板配置的作业主机，无需再选。CMDB 中的主机/应用仅为资产台账，不再作为执行输入源。

| # | 模块 | 一句话说明 |
| --- | --- | --- |
| 1 | 登录鉴权 | 本地账号 + LDAP/OAuth SSO，RBAC 权限，MFA 可开关/可强制 |
| 2 | CMDB | 主机与应用服务管理（资产台账），手工录入 + Excel 导入，预留自动发现 |

| 4 | 工单中心 | 选模板填参数提交（标题=模板名）；审批规则在模板内独立配置（可免审/多节点），通过后自动执行 |
| 5 | 安全审计 | 登录/操作/作业/审批全行为审计，可检索、可导出、按配置保留 |
| 6 | 通知集成 | 邮件、Webhook、Teams 落地；钉钉/飞书/企业微信留接口 |

### 1.4 V1 明确不做（Out of Scope）

### 1.5 用户与规模

- 部署环境：企业内网，Docker Compose 单机部署。
- 规模目标：主机 **1000+ 台**，平台用户 **1000+ 人**。
- 典型用户：运维工程师、运维负责人（审批人）、平台管理员、审计人员。

## 2. 角色与权限（RBAC）

### 2.1 权限模型

采用 **用户（User）— 角色（Role）— 权限点（Permission）** 三级模型：

- 一个用户可绑定多个角色，权限取并集；
- 权限点按"模块:操作"粒度定义（如 `cmdb:write`、`ticket:approve`），共 20 个权限点；
- 角色可由管理员自定义，系统内置 4 个默认角色（admin/ops/approver/auditor，不可删除、内置角色权限矩阵不可改）。

## 3. 功能需求

### 3.1 模块一：登录鉴权

#### 3.1.1 认证方式

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| AUTH-01 | 本地账号密码登录（默认方式）；密码 bcrypt 加密存储 | P0 |
| AUTH-02 | 密码策略：最小长度、复杂度（大小写+数字+特殊字符可配置）、连续登录失败 N 次锁定 M 分钟（可配置） | P0 |
| AUTH-03 | LDAP/AD 对接：管理员配置 LDAP 服务器后，用户可用域账号登录，首次登录自动建用户（默认角色可配置） | P1 |
| AUTH-04 | OAuth2/OIDC 对接：支持配置一个标准 OIDC 提供方（授权码模式），登录页展示 SSO 入口 | P1 |
| AUTH-05 | 会话管理：JWT（Access + Refresh），Access 短时效、Refresh 可配置；支持主动登出使 Refresh 失效 | P0 |

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| MFA-01 | 基于 TOTP（兼容 Google Authenticator / Microsoft Authenticator） | P0 |

| MFA-03 | 强制模式下，未绑定 MFA 的用户登录后被引导进入绑定流程，绑定完成前不能进入平台 | P0 |
| MFA-04 | 管理员可为指定用户重置 MFA（用户丢失设备场景） | P0 |

#### 3.1.3 用户与角色管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |

| USER-02 | 角色管理：自定义角色，勾选权限点；内置角色不可删除 | P0 |

#### 3.3.4 执行引擎

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| EXEC-01 | Shell 模式：平台 SSH 连接**作业主机**，在其 workspace 执行 Shell 脚本 | P0 |
| EXEC-02 | Ansible 模式：平台 SSH 连接**作业主机**，在其 workspace 执行 `ansible-playbook` / `ansible` 命令（inventory 与 playbook 由步骤脚本自行定义，平台不感知目标主机） | P0 |
| EXEC-03 | 执行策略：单步超时（`asyncio.wait_for` 步骤级）、失败中断策略（`fail_fast`：当前步骤失败是否中断后续步骤） | P0 |
| EXEC-04 | 运行时操作：**撤销**（cancel，仅审批中，整单作废不进执行）、**中止**（abort，queued/running/paused，不再执行后续步骤，当前在跑步骤默认不打断、跑完后 execution 置 terminated、工单置 interrupted(user_abort)，后续步骤置 skipped）、**暂停/恢复**（pause/resume，running↔paused，当前步骤跑完后停住不进入下一步骤，恢复从下一步骤继续）、**强制中止**（force-abort，kill 作业主机上当前在跑步骤进程 best-effort，当前步骤置 terminated，高风险独立审计） | P0 |
| EXEC-05 | 实时日志：按**步骤维度**实时滚动输出（REST 长轮询：/events 事件长轮询 + /logs 每 2s 按行偏移增量拉取，WebSocket 已弃用）；前端可切换步骤查看对应日志；日志持久化，事后可完整回看 | P0 |
| EXEC-06 | 执行结果：按**步骤**维度展示状态（等待/执行中/成功/失败/超时/已跳过/已终止）+ 汇总统计 | P0 |
| EXEC-07 | 执行记录列表：按工单/模板/发起人/时间/结果筛选 | P0 |
| EXEC-08 | **Pipeline 线性流水线**：工单包含 1~N 个步骤（来自模板内嵌步骤的提交时快照），步骤严格串行；每步在模板配置的作业主机 workspace 执行一次；步骤失败（按失败策略判定）则中断后续步骤；不支持分支/并行编排 | P0 |

### 3.4 模块四：工单中心

#### 3.4.1 工单实例（基于模板的一次具体提交）

工单中心只能使用模板，不能定义模板；不提供审批流/表单字段/通知/执行策略的任何配置能力。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |

## 4. 核心业务流程

### 4.1 发布工单主流程

<!-- v2.2 变更: 整段重写。去"选应用→带出主机"，改为"选模板→填参"；执行改为"步骤串行，每步在作业主机 workspace 执行" -->

```
管理员维护作业主机列表(CRUD + 连通性测试 + 启用/禁用)
运维创建模板(选作业主机 + 编排Pipeline步骤 + 执行策略 + 审批规则 + 通知规则)
   │
   └─→ 工单中心选模板填参数提交
          │
          ├─ 审批开关=关 ──────────────────────┐
          │                                    ▼
          └─ 审批开关=开 → 逐级审批            自动执行
                 │              │                  │
                 │ 任一级驳回    │ 全部通过          ▼
                 ▼              └──────────→  Pipeline执行(步骤串行，每步在作业主机workspace执行，实时日志)
              工单关闭(通知创建人)                  │  步骤失败→中断后续步骤
                                           ┌────────┴────────┐
                                           ▼                 ▼
                                      执行成功           执行失败/终止
                                           └───── 通知创建人 ─────┘
                                                全程写审计日志
```

### 4.2 登录流程（含 MFA）

```
输入账号密码(或 SSO 跳转) → 认证成功
   → MFA 关闭：直接进入平台
   → MFA 可选：已绑定则校验 TOTP，未绑定直接进入
   → MFA 强制：已绑定则校验 TOTP；未绑定进入强制绑定流程
每次登录成功/失败均写审计日志；失败超限锁定账号
```

1. 管理员可完成：用户/角色/MFA 策略/审批流/通知渠道/凭据的全部配置。
2. 运维可完成：录入（含 Excel 导入）1000 台规模主机与应用、维护多对多关联（资产台账）。

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | SSH 凭据存放 | 不放 CMDB 主机表，独立凭据管理（本文档 CRED-01） |
| 2 | 环境区分 | 仅主机有环境字段；审批流不按环境区分 |
| 3 | 驳回后流转 | 直接关闭，提供"复制工单"降低重建成本 |
| 4 | 钉钉/飞书/企业微信 | V1 只留渠道抽象接口 |
| 5 | 自动发现 | V1 只留扩展点 |
| 6 | 作业主机（job_host） | 类 Jenkins agent 通用执行节点；管理员在系统设置维护多台作业主机列表（CRUD + 连通性测试 + 启用/禁用），每台绑定一条 SSH 凭据；模板配置时单选其一 |
| 7 | Pipeline 形态 | 线性多步骤流水线（步骤串行，每步在作业主机 workspace 执行一次），不做分支/并行编排 |
| 8 | 作业主机确定方式 | 模板配置时选定作业主机，工单提交时取模板配置的作业主机并固化快照；不可在工单中更改 |
| 9 | 执行触发 | 审批通过（或审批开关关闭时提交）后自动执行，无手动触发环节 |
| 10 | 自审批 | 允许审批人审批自己创建的工单 |
| 11 | CMDB 与执行的关系 | CMDB（主机/应用）退化为资产台账，与工单执行完全解耦；工单不再引用 CMDB 主机作为执行对象 |
