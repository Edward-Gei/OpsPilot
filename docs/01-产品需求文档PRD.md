## 1. 产品概述

### 1.1 产品定位

面向企业内网环境的轻量级自动化运维平台，围绕"**发布工单驱动的作业执行**"核心链路，提供资源管理（CMDB）、作业执行（Shell/Ansible 流水线）、工单中心、安全审计和消息通知能力。

### 1.2 核心业务闭环

```
CMDB 维护主机/应用 → 模板管理定义工单模板（目标应用 + 步骤编排(内嵌脚本) + 执行策略 + 审批规则 + 通知规则 + 权限范围）
    → 工单中心选模板填参数提交（标题=模板名，目标主机取应用关联的全部主机）
    → 模板内审批流依次审批（每模板独立配置，可免审） → 通过后自动执行 Pipeline（SSH/Ansible，实时日志）
    → 结果通知（邮件/Webhook/Teams） → 全程审计留痕
```

### 1.3 V1 范围（In Scope）

| # | 模块 | 一句话说明 |
| --- | --- | --- |
| 1 | 登录鉴权 | 本地账号 + LDAP/OAuth SSO，RBAC 权限，MFA 可开关/可强制 |
| 2 | CMDB | 主机与应用服务管理，手工录入 + Excel 导入，预留自动发现 |
| 3 | 作业执行 | 工单模板（内嵌多步骤脚本）+ 线性 Pipeline，SSH 直连/作业主机 Ansible，执行控制 + 实时日志 |
| 4 | 工单中心 | 选模板填参数提交（标题=模板名）；审批规则在模板内独立配置（可免审/多节点），通过后自动执行 |
| 5 | 安全审计 | 登录/操作/作业/审批全行为审计，可检索、可导出、按配置保留 |
| 6 | 通知集成 | 邮件、Webhook、Teams 落地；钉钉/飞书/企业微信留接口 |

### 1.4 V1 明确不做（Out of Scope）

告警中心、巡检中心、AI 助手、可观测平台、配置中心、复杂流程编排、发布平台、数据库运维、云资源自动同步、插件市场。

### 1.5 用户与规模

- 部署环境：企业内网，Docker Compose 单机部署。
- 规模目标：主机 **1000+ 台**，平台用户 **1000+ 人**。
- 典型用户：运维工程师、运维负责人（审批人）、平台管理员、审计人员。

## 2. 角色与权限（RBAC）

### 2.1 权限模型

采用 **用户（User）— 角色（Role）— 权限点（Permission）** 三级模型：

- 一个用户可绑定多个角色，权限取并集；
- 权限点按"模块:操作"粒度定义（如 `cmdb:write`、`ticket:approve`），共 20 个权限点；
- 角色可由管理员自定义，系统内置 4 个默认角色（admin/ops/approver/auditor，不可删除、内置角色权限矩阵不可改）。

### 2.2 内置角色与权限矩阵

| 权限点 | 管理员 admin | 运维 ops | 审批人 approver | 审计员 auditor |

| CMDB 查看 | ✔ | ✔ | ✔ | ✔ |
| CMDB 新增/编辑/删除/导入 | ✔ | ✔ | — | — |

## 3. 功能需求

### 3.1 模块一：登录鉴权

#### 3.1.1 认证方式

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| AUTH-01 | 本地账号密码登录（默认方式）；密码 bcrypt 加密存储 | P0 |
| AUTH-02 | 密码策略：最小长度、复杂度（大小写+数字+特殊字符可配置）、连续登录失败 N 次锁定 M 分钟（可配置） | P0 |
| AUTH-03 | LDAP/AD 对接：管理员配置 LDAP 服务器后，用户可用域账号登录，首次登录自动建用户（默认角色可配置） | P1 |
| AUTH-04 | OAuth2/OIDC 对接：支持配置一个标准 OIDC 提供方（授权码模式），登录页展示 SSO 入口 | P1 |
| AUTH-05 | 会话管理：JWT（Access + Refresh），Access 短时效、Refresh 可配置；支持主动登出使 Refresh 失效 | P0 |

#### 3.1.2 MFA（双因素认证）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| MFA-01 | 基于 TOTP（兼容 Google Authenticator / Microsoft Authenticator） | P0 |
| MFA-02 | 全局开关：`关闭 / 可选（用户自行开启） / 强制（所有用户必须绑定）`，管理员配置 | P0 |
| MFA-03 | 强制模式下，未绑定 MFA 的用户登录后被引导进入绑定流程，绑定完成前不能进入平台 | P0 |
| MFA-04 | 管理员可为指定用户重置 MFA（用户丢失设备场景） | P0 |

#### 3.1.3 用户与角色管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| USER-01 | 用户管理：新增/禁用/启用/重置密码/分配角色；来源标记（本地/LDAP/OAuth） | P0 |
| USER-02 | 角色管理：自定义角色，勾选权限点；内置角色不可删除 | P0 |
| USER-03 | 个人中心：修改密码（本地账号）、绑定/查看 MFA 状态、自助修改显示名/邮箱 | P0 |
| USER-04 | 访问密钥：个人 API Token 自助管理（创建/列表/删除），`Bearer opsp_xxx` 直调平台 API，权限与本人实时一致；明文仅创建时展示一次，每人上限 10 个 | P1 |

| HOST-04 | 状态枚举：`在线 / 离线 / 维护中`，手工维护 | P0 |

### 3.3 模块三：作业执行

#### 3.3.1 凭据管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| CRED-01 | SSH 凭据集中管理：名称、登录用户、认证方式（密码/私钥）、密文内容；密文 AES-256-GCM 加密存储，任何接口不回显明文 | P0 |
| CRED-02 | 仅管理员可管理凭据；工单/模板中只引用凭据名称 | P0 |

#### 3.3.2 工单模板库（规则定义，模板管理维护）

工单模板是“规则定义”：所有工单规则相关配置都必须在模板管理中完成。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| TPL-01 | 模板基本信息：名称、类型（`发布/变更/运维/其他`）、说明、目标应用（从 CMDB 选择，执行范围=应用关联全部主机）、启用/禁用状态 | P0 |
| TPL-02 | 步骤编排：1~N 步严格串行，每步内嵌脚本（名称、类型 `Shell/Ansible Playbook`、内容、参数定义、SSH 凭据、超时）；内容支持 `{{ 变量 }}` 占位，提交工单时填参渲染 | P0 |
| TPL-03 | 参数定义：变量名/显示名/默认值/是否必填/是否固定值/说明；固定值参数锁定默认值，提交人不可见不可改；提交表单=各步骤参数自动汇总（同名合并） | P0 |
| TPL-04 | 模板内还需配置：执行策略（并发/分批/超时/失败策略）、审批规则（见 3.4.2）、通知规则（事件→接收人→渠道）、权限范围（可提交角色，空=不限） | P0 |
| TPL-05 | 规则任一变更自动产生新版本（全量快照），历史版本可查；工单提交时固化模板版本 | P1 |
| TPL-06 | 工单中**只能选择模板**，不允许自由填写脚本内容与任何规则配置（安全约束） | P0 |

#### 3.3.3 执行引擎

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| EXEC-01 | Shell 模式：平台通过 SSH 直连目标主机执行脚本（免 agent） | P0 |
| EXEC-02 | Ansible 模式：平台 SSH 连接**作业主机**（安装了 Ansible 的跳板机，管理员配置），动态生成 inventory 与 playbook 后执行 `ansible-playbook` / `ansible` 命令 | P0 |
| EXEC-03 | 执行控制：并发数（同时执行的主机数）、分批执行（每批主机数 + 批间暂停确认可选）、单机超时、失败中断策略（任一主机失败是否中断后续批次） | P0 |
| EXEC-04 | 运行时操作：**撤销**（cancel，仅审批中，整单作废不进执行）、**中止**（abort，queued/running/paused，停止派发后续目标，在跑目标不打断，未派发置 skipped，工单终态 interrupted）、**暂停/恢复**（pause/resume，running↔paused，暂停不打断在跑目标只停止派发，恢复从停住处继续）、**强制中止**（force-abort，对在跑目标 best-effort 强杀，高风险独立审计） | P0 |
| EXEC-05 | 实时日志：按主机维度实时滚动输出（WebSocket，断线自动降级长轮询）；日志持久化，事后可完整回看 | P0 |
| EXEC-06 | 执行结果：按步骤 × 主机两级维度展示状态（等待/执行中/成功/失败/超时/已跳过/已终止）+ 汇总统计 | P0 |
| EXEC-07 | 执行记录列表：按工单/应用/模板/发起人/时间/结果筛选 | P0 |
| EXEC-08 | **Pipeline 线性流水线**：工单包含 1~N 个步骤（来自模板内嵌步骤的提交时快照），步骤严格串行；步骤内主机按并发/分批策略执行；步骤失败（按失败策略判定）则中断后续步骤；不支持分支/并行编排（非复杂流程编排） | P0 |

### 3.4 模块四：工单中心

#### 3.4.1 工单实例（基于模板的一次具体提交）

工单中心只能使用模板，不能定义模板；不提供审批流/表单字段/通知/执行策略的任何配置能力。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| TICKET-01 | 提交工单：选择模板（仅启用且在我权限范围内）→ 填写参数（模板汇总参数表单）→ 提交；标题使用模板名，无草稿，提交即生效 | P0 |
| TICKET-02 | **目标主机自动确定**：取模板目标应用关联的**全部主机**，不可手动增删；提交前展示主机/步骤/审批节点/策略只读预览；提交时固化五重快照（主机/步骤内容/审批节点/策略/模板版本），后续模板或 CMDB 变更不影响已提交工单 | P0 |
| TICKET-03 | 工单状态机：`审批中 → 执行中 → 成功/失败`；`已驳回`、`已撤回` 为终态；模板免审时提交直接进入执行队列；**审批通过后自动进入执行队列**，无手动触发环节 | P0 |
| TICKET-04 | 审批被驳回后工单**直接关闭**（终态），如需重发需重新选模板提交新工单 | P0 |
| TICKET-05 | 创建人可在“审批中”阶段撤回工单（仅当模板允许撤回；进入执行后只能用运行时“停止”） | P0 |
| TICKET-06 | 工单详情（只读）：基本信息、参数、目标应用与主机清单、Pipeline 步骤视图、审批进度时间线、执行进度与日志入口 | P0 |
| TICKET-07 | 工单类型随模板（`发布/变更/运维/其他`），实例存类型快照 | P0 |

#### 3.4.2 审批规则（配置在每个工单模板内部，无全局审批流）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FLOW-01 | 每个模板独立配置是否需要审批；免审模板的工单提交后直接自动执行；**不设全局审批开关** | P0 |
| FLOW-02 | 模板内可配置多节点审批（1~10 节点），每节点指定一个**审批角色**；节点间依次推进 | P0 |
| FLOW-03 | 节点内审批方式：`或签/会签/依次审批`可配置；V1 仅**或签**生效（角色内任一成员处理即定节点结果），会签/依次仅存配置后续版本开放；任一节点驳回则工单关闭 | P0 |
| FLOW-04 | 审批操作：通过/驳回，审批意见通过可选、驳回必填 | P0 |
| FLOW-05 | 审批人**可以**审批自己创建的工单（审计日志完整留痕） | P0 |
| FLOW-06 | 待办列表：审批人可见“待我审批”（当前节点角色 ∩ 我的角色）的工单列表与角标提醒 | P0 |
| FLOW-07 | 模板内可配置是否允许撤回/转交/加签；V1 仅**撤回**生效，转交/加签仅存配置后续版本开放 | P0 |

### 3.5 模块五：安全审计

### 3.6 模块六：通知集成

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| NOTIFY-01 | V1 落地渠道：**邮件（SMTP）、Webhook（自定义 URL+密钥签名）、Microsoft Teams**；钉钉/飞书/企业微信仅预留渠道接口（插件式渠道抽象，不实现） | P0 |

## 4. 核心业务流程

### 4.1 发布工单主流程

```
运维创建工单(选应用→自动带出全部关联主机 + 编排Pipeline步骤 + 执行策略)
   │
   ├─ 审批开关=关 ──────────────────────┐
   │                                    ▼
   └─ 审批开关=开 → 逐级审批            自动执行
          │              │                  │
          │ 任一级驳回    │ 全部通过          ▼
          ▼              └──────────→  Pipeline执行(步骤串行，步内分批/并发/实时日志)
       工单关闭(通知创建人)                  │  步骤失败→中断后续步骤
                                   ┌────────┴────────┐
                                   ▼                 ▼
                              执行成功           执行失败/终止
                                   └───── 通知创建人 ─────┘
                                        全程写审计日志
```

### 4.2 登录流程（含 MFA）

```
输入账号密码(或 SSO 跳转) → 认证成功
   → MFA 关闭：直接进入平台
   → MFA 可选：已绑定则校验 TOTP，未绑定直接进入
   → MFA 强制：已绑定则校验 TOTP；未绑定进入强制绑定流程
每次登录成功/失败均写审计日志；失败超限锁定账号
```

## 6. 验收标准（V1 DoD）

1. 管理员可完成：用户/角色/MFA 策略/审批流/通知渠道/凭据的全部配置。
2. 运维可完成：录入（含 Excel 导入）1000 台规模主机与应用、维护多对多关联。
3. 完整跑通：选应用创建工单（自动带出全部关联主机）→ 一级审批（开/关两种模式）→ 自动执行含 Shell 与 Ansible 步骤的多步 Pipeline（管理员先在系统设置页配置 Ansible 作业主机并测试连通性）→ 实时日志 → 结果通知（邮件/Webhook/Teams 至少各验证一次）。
4. 执行控制验证：并发、分批+批间确认、超时、失败中断、撤销、中止、暂停、恢复（含强制中止）全部可用。
5. 审计页可检索并导出上述全流程产生的日志；保留时长清理任务可验证。
6. Docker Compose 在纯内网环境一键部署成功。

## 7. 遗留决策与假设记录

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | SSH 凭据存放 | 不放 CMDB 主机表，独立凭据管理（本文档 CRED-01） |
| 2 | 环境区分 | 仅主机有环境字段；审批流不按环境区分 |
| 3 | 驳回后流转 | 直接关闭，提供"复制工单"降低重建成本 |
| 4 | 钉钉/飞书/企业微信 | V1 只留渠道抽象接口 |
| 5 | 自动发现 | V1 只留扩展点 |
| 6 | 作业主机（Ansible 跳板机） | 由管理员在系统设置中配置（地址+凭据），Ansible 需预装在该主机 |
| 7 | Pipeline 形态 | 线性多步骤流水线（步骤串行，每步一个模板），不做分支/并行编排 |
| 8 | 目标主机确定方式 | 强制取应用关联的全部主机，不可手动增删；提交时固化主机快照 |
| 9 | 执行触发 | 审批通过（或审批开关关闭时提交）后自动执行，无手动触发环节 |
| 10 | 自审批 | 允许审批人审批自己创建的工单 |
