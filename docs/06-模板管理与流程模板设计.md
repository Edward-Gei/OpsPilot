# 模板管理与流程模板设计

## 1. 文档状态

| 项目 | 内容 |
| --- | --- |
| 适用阶段 | V1 竣工实现 |
| 方案状态 | 已实现并验收 |
| 设计目标 | 复用执行流程，同时为每个工单入口独立定义参数和通知 |
| 事实来源 | `backend/app/models/job.py`、`backend/app/models/ticket.py`、`backend/app/services/template_service.py` |

模板管理包含两个独立对象：工单模板和流程模板。工单模板面向提单人，流程模板面向执行配置；流程模板可被多个工单模板引用。

## 2. 管理入口

侧边栏的“模板管理”下提供“工单模板”和“流程模板”两个页面。两个页面共享列表、抽屉、弹窗和状态开关样式，但分别调用 `/templates` 与 `/process-templates` 接口。

## 3. 领域模型

### 3.1 工单模板

工单模板是工单提交入口，字段如下：

| 字段 | 说明 |
| --- | --- |
| `name` | 唯一名称 |
| `type` | `release`、`daily_ops`、`other` |
| `description` | 入口说明 |
| `job_host_id` | 执行节点，单选；必须是启用的作业主机 |
| `process_template_id` | 引用一个启用的流程模板 |
| `params_schema` | 本入口的参数定义 |
| `generator_script` / `generator_timeout` | 动态参数生成脚本及超时 |
| `allow_withdraw` | 是否允许创建人在审批中撤回 |
| `notify_rules` | 事件、接收人和渠道规则 |
| `visible_role_ids` | 可见角色；空数组表示所有具有 `ticket:write` 的角色 |
| `status` | `enabled` 或 `disabled` |

工单模板不保存步骤、执行策略或审批角色；这些内容来自流程模板。工单模板也不保存凭据密文。

### 3.2 流程模板

流程模板可复用，字段包括名称、说明、状态、执行策略和有序步骤。

执行策略当前为：

| 字段 | 说明 |
| --- | --- |
| `timeout` | 每个步骤的默认超时秒数，1 至 86400 |
| `fail_fast` | 当前步骤失败后是否跳过后续步骤 |
| `kill_on_stop` | 停止时是否尝试强制结束当前连接 |

流程模板不保存参数契约或动态生成脚本。保存后，新工单使用最新配置；已经创建的工单只读取自己的流程快照。

### 3.3 流程步骤

步骤按 `step_order` 串行执行，每步包含：

- `name`：步骤名称；
- `script_type`：`shell` 或 `playbook`；
- `content`：脚本或 Playbook 内容；
- `timeout`：步骤超时秒数；
- `approval_role_id`：可空；非空时该角色的任意一名成员可以审批。

步骤前审批只有一个角色，不支持多角色、会签、转交或加签。驳回会直接终止工单。

## 4. 参数与动态生成

参数定义属于工单模板，因此同一流程模板被不同入口复用时，可以有不同参数。

### 4.1 参数来源

| 来源 | 行为 |
| --- | --- |
| `fixed` | 必须配置 `default`，提交人不填写，服务端直接使用 |
| `user` | 提交人填写或选择，可配置默认值 |
| `generated` | 由生成脚本返回，不显示普通输入框 |

参数名必须匹配 `[A-Za-z_][A-Za-z0-9_]*` 且不能重复。输入类型为 `text` 或 `enum`；枚举参数必须有候选项，默认值必须属于候选项。

### 4.2 动态参数预生成

用户在提交页点击“下一步”时，调用 `POST /tickets/prepare` 在作业主机执行生成脚本。脚本超时或执行失败时不能创建工单。脚本可以返回固定值或候选列表；列表在确认页提供单选，默认选择第一项。

生成脚本执行前会使用当前已准备的固定值和用户参数进行 Jinja2 渲染，可通过 `{{ 参数名 }}` 引用；同时通过 `PARAMS_JSON` 环境变量提供完整参数 JSON。

预生成结果以短期 `prepare_id` 保存。提交工单时携带 `prepare_id` 和普通参数，服务端复用并消费预生成结果，校验后创建快照。预生成本身不写单独审计记录。

## 5. 工单快照

创建工单时服务端读取启用的工单模板、流程模板和作业主机，并保存：

- 工单模板类型、名称和参数结果；
- 作业主机连接信息快照；
- 流程名称、执行策略和全部步骤内容；
- 每步审批角色；
- 动态生成配置和生成结果；
- `allow_withdraw` 和通知规则所需的业务信息。

后续模板、流程模板、作业主机或凭据配置变化不影响已创建工单。执行步骤只使用工单快照和运行时解密的作业主机凭据。

## 6. 执行与审批

流程步骤严格串行：

1. 无审批角色的步骤直接进入执行。
2. 有审批角色的步骤将工单置为 `approving`，该角色任一成员通过后继续。
3. 审批通过后自动进入执行队列，不需要手工启动。
4. 任意审批人驳回，工单进入 `rejected` 终态，不执行后续步骤。
5. 执行期间支持暂停、恢复、中止和强制中止；审批中支持创建人撤回（需模板允许）。

## 7. 启停、编辑与删除

- 停用工单模板后不能新建工单，已创建工单不受影响。
- 停用流程模板后不能被新的工单模板引用，也不能用于新的工单；已引用的工单模板仍可保留，流程模板可编辑。
- 流程模板被工单模板引用时不能删除。
- 工单模板存在 `approving`、`queued`、`running` 或 `paused` 工单时不能删除。
- 无进行中工单的工单模板可以删除；历史工单通过快照独立查看。
- 复制由前端读取详情后预填编辑器，确认保存时调用普通创建接口；批量删除由前端逐条调用删除接口，仍遵守权限和保护规则。

## 8. API

流程模板：`GET/POST /process-templates`、`GET/PUT/DELETE /process-templates/{id}`、`PUT /process-templates/{id}/status`。

工单模板：`GET/POST /templates`、`GET/PUT/DELETE /templates/{id}`、`PUT /templates/{id}/status`。

工单提交相关：`GET /tickets/templates`、`GET /tickets/templates/{id}/form`、`POST /tickets/prepare`、`POST /tickets`。

## 9. 验收要点

- 工单模板编辑器只出现入口、参数、动态生成、通知和可见角色配置。
- 流程模板编辑器只出现步骤、步骤前审批和执行策略配置。
- 停用模板的提交和引用规则正确，引用保护正确。
- 固定值、用户输入和动态列表参数均能正确生成并进入工单快照。
- 每个步骤最多一个审批角色；角色任一成员通过即可继续，驳回直接终止。
- 提交后修改模板、流程模板、作业主机或凭据，不改变既有工单的快照和执行结果。
