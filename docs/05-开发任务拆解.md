## 1. 里程碑与依赖顺序

> 实施结果：M0~M8 里程碑主线已全部交付并联调通过；后续按需追加的增量需求见 §2.9「增量任务台账」。下文各里程碑标注 ✅ 表示已完成。

```
M0 工程骨架与部署基座
 └► M1 登录鉴权+RBAC（含审计写入器基座）
     └► M2 CMDB ──┐
     └► M3 凭据与工单模板 ─┤
                      └► M4 工单中心（模板内审批流）
                          └► M5 执行引擎（Worker/SSH/Ansible/实时日志）
                              └► M6 通知集成
                                  └► M7 审计完善与导出
                                      └► M8 前端整合、联调与验收
```

- **审计是横切能力**：M1 交付 `audit.log()` 写入器与登录审计；M2~M7 各模块开发时同步埋点。
- **前端随模块推进**：每个模块的后端 API 完成后立即开发对应页面，M8 做整合与全链路验收。

### M3 凭据与工单模板 ✅

工单模板承载全部规则：基本信息/作业主机/步骤编排（内嵌脚本）/执行策略/审批规则/通知规则/权限范围/凭据引用/版本。

| 任务 | 交付物 |
| --- | --- |
| M3-1 加密工具 | AES-256-GCM 字段加解密（core/security），单测覆盖 |
| M3-2 凭据 API + 页面 | CRUD（密文不回显）、引用保护 |
| M3-3 工单模板 API + 页面 | 全量配置 CRUD + 启用/禁用 + 自动升版（全量快照）+ 版本历史；模板编辑器七块（基本信息/步骤编排/执行策略/审批规则/通知规则/权限范围/版本历史）、参数 schema 编辑器（含固定值）、代码编辑器（shell/yaml 高亮） |

**验收**：改模板规则自动升版且旧版本可查；凭据任何接口不回显明文；审批节点/通知规则/权限范围随模板保存。

### M4 工单中心 ✅

工单中心只能使用模板：选模板 → 填参数 → 提交（标题=模板名，无草稿）。**无全局审批流配置**。

| 任务 | 交付物 |
| --- | --- |
| M4-1 提交 API | 可用模板列表（enabled+权限范围过滤）、提交表单描述（汇总参数+只读预览）、提交（六重快照：作业主机/步骤内容/审批节点/策略/版本/引用凭据；免审直接入队）、状态机（7 态）、cancel（撤回）、todo 列表 |
| M4-2 审批 API | approve/reject、节点依次推进（节点内角色任一成员或签）、末节点通过触发执行入队（M5 前先打桩）、通知事件按模板 notify_rules 发射（M6 前先落 record） |
| M4-3 页面 | 工单列表 + 提交抽屉（选模板→填参数，含主机/步骤/审批节点只读预览）、工单详情（只读，审批时间线）、待办审批页（角标） |

**验收**：免审/多节点两种模板状态流正确；节点依次推进/驳回关闭/撤回正确；六重快照固化（提交后改模板/作业主机不影响工单）；权限范围外用户不可见模板。

### M5 执行引擎（核心，工作量最大） ✅

| 任务 | 交付物 |

## 3. 测试策略

- **单测（pytest + pytest-asyncio）**：core 安全工具、状态机流转、调度器超时/失败策略逻辑（mock SSH）——这些纯逻辑模块必须有单测。
- **接口测试**：httpx AsyncClient 覆盖认证、RBAC 拒绝路径、工单状态机非法迁移。
- **执行引擎集成测试**：compose 起 `linuxserver/openssh-server` 容器模拟作业主机。
- 前端 V1 不做自动化测试，靠联调走查。

## 4. 编码顺序说明

按 M0 → M8 严格顺序推进；每个里程碑完成后停下让用户验收/审阅，再进入下一个。
